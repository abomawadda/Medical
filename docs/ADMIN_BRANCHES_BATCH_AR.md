# العناوين المتعددة والمعالجة الجماعية — 4.3.0

طلب المالك إضافة أكثر من عنوان عند إنشاء سجل، وتصنيف المستشفى الجديدة «مستشفى استثماري». وحصر المعالجة الجماعية صراحة في الإظهار والإخفاء والإيقاف؛ أضيف الاستئناف كعكس للإيقاف دون تعديل بيانات مشتركة أو حذف جماعي.

## إنشاء سجل له فروع

العنوان الموجود بالنموذج هو الفرع الرئيسي. زر «+ إضافة عنوان / فرع» يضيف حتى تسعة فروع إضافية (عشرة إجمالًا). لكل فرع مركز وعنوان وأرقام محمول وأرضي ومختصر ومواعيد وخريطة واسم مختصر مستقل. لا تنسخ أرقام الرئيسي أو مواعيده أو خريطته إلى الفروع تلقائيًا. الاسم ونوع الجهة والمستفيدون والتعاقد والصورة مشتركة كما يوضح النموذج؛ تعديل تفاصيل كل فرع بعد الحفظ متاح من سجله.

تحفظ الفروع كلها في معاملة واحدة بعد التحقق من البيانات والروابط والهواتف وعدم تكرار العنوان داخل المركز نفسه. خطأ فرع يمنع حفظ المجموعة كلها، ولا تنشأ مجموعة ناقصة. الإعادة بالمعرف الرئيسي نفسه بعد إنشاء ناجح لا تنشئ فروعًا إضافية خفية. غياب نشر الخدمة الداعمة يمنع الحفظ ويترك النموذج دون فقد مدخلاته.

للجهات معرف تنظيمي خادمي مشترك يحفظ البطاقة الجامعة، ولكل فرع معرف مستقل وتعاقد وحالة وموقع وتقييم. مقار الطبيب تشترك أيضًا في معرف الطبيب، وفق نموذج الطبيب الحالي. المستشفى المستقلة تتعاقد باسمها ومعرف فرعها نفسه؛ لا يُربط فرعها الجديد بالمقر الرئيسي كتعاقد مستشفى أم بالتخمين. قوائم المستشفيات تعرض تفاصيل الفرع للتفريق بينها.

لا يستطيع طلب تعديل عادي زرع معرف تنظيمي أو ربط سجلات قديمة اعتباطيًا؛ ينشأ الرابط خادميًا في عملية الإنشاء الجديدة، ويُحفظ عند تحرير الفرع. إضافة فروع لجهة قديمة وإعادة ترتيبها أو فصلها من داخل الإدارة تطوير لاحق؛ الإضافة المتعددة الحالية تخص إنشاء سجل جديد، كما طلب المالك.

تصنيف المستشفى الجديدة افتراضيًا «مستشفى استثماري» وقابل للتعديل من قائمة نوع الجهة. يحفظ الخادم التصنيف ويظهر في البطاقة، ولا يُعاد تصنيف مستشفيات حكومية أو جامعية قديمة تلقائيًا.

## تحديد ومعالجة عدة سجلات

- مربع لكل سجل قابل لمعالجة الحالة، ومربع لتحديد السجلات المعروضة على الصفحة فقط. النشرات والتعليمات خارج هذه العملية لأن نشرها له مرجع وسريان وقواعد مستقلة.
- «معالجة المحدد» يعرض أسماء ومعرفات ومراكز السجلات وعددها، ثم اختيار الإخفاء أو الإظهار أو الإيقاف المؤقت أو الاستئناف.
- التحديد يُمسح عند إعادة عرض القائمة أو تغيير البحث أو التصفية؛ لا تبقى سجلات محددة غير ظاهرة للمستخدم.
- الحد الأقصى 50 سجلًا في الطلب. لا يشمل القرار مقار طبيب أخرى لم تحدد، بينما حالة المستشفى تؤثر على خدماتها التابعة وفق النظام الحالي، ويظهر توضيح ذلك قبل التنفيذ.
- الإظهار لا يعتمد جهات محجوبة تلقائيًا؛ يتطلب إقرار المدير الصريح بتعاقداتها، مع اكتمال جهة التعاقد. إظهار فرع تابع لمستشفى مخفية يحتاج إظهار المستشفى أولًا أو ضمها إلى العملية نفسها.
- يراجع الخادم جميع المعرفات والنسخ والصلاحية قبل الحفظ، وتراجعها معاملة Firestore مرة أخرى. تغير أي سجل يلغي العملية كاملة بحالة تعارض، دون حفظ جزئي. يعود المستخدم لتحديث القائمة وإعادة التحديد.
- لا توجد كتابة جماعية للأسماء أو المراكز أو المستفيدين، ولا حذف جماعي، ولا أخبار أعضاء تلقائية.

## التشغيل والخصوصية

الصلاحية للمدير فقط، وسجل التدقيق في Medical. MyNekaba للقراءة فقط ولم يغير هذا الإصدار بيانات الأعضاء أو أدوارهم أو حساباتهم أو تقييماتهم.

القدرتان `admin-batch-v1` و`structured-branches-v1` تعلنان دعم الخدمة، والواجهة تتحقق من توفرهما قبل الحفظ الجديد. ظهور النموذج أو نشر Vercel لا يعني نشر Firebase. إلى تفعيل الخدمة تبقى الإضافة المفردة والإجراءات المفردة على مساراتها القائمة، وتظهر ملاحظة التفعيل للإدارة فقط.

من Cloud Shell:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only && bash scripts/deploy-medical.sh --existing-config
```

فحص عام دون بيانات دخول:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --vercel --require-admin-batch
```

## نتيجة التحقق

- 88 اختبار وحدة ناجح، يشمل منع العضو من العمليات الإدارية، منع الاعتماد الضمني، رفض النسخ المتعارضة والتحديد المكرر، وحدة معرف الطبيب عبر عناوينه، واستقلال أرقام المستشفى الجديدة وحماية المعرف التنظيمي.
- رحلة المتصفح الكاملة ناجحة دون أخطاء JavaScript في 320 و390 و768 و1440: تحديد سجلين وإيقافهما ثم استئنافهما، وإضافة مستشفى بتصنيفها الافتراضي وفرعين مختلفين وعرضهما للعضو.
- محاكي Firestore ناجح: إنشاء الفرعين في معاملة، وتغيير حالتهما معًا، ورفض النسخة المتعارضة دون تغيير أي فرع، مع بقاء مصدر النقابة دون تعديل.
- بناء الأصول وفحص حدود النشر ناجح. التفعيل الإنتاجي للعمليات الجديدة يثبت بفحص القدرتين بعد نشر Medical Firebase؛ لا يكفي نشر الواجهة.
