# تصحيح دفعات الدليل وخطط المراجعة الخاصة — 4.19.0

## النطاق والحالة

استكمال C06/C07/O05 داخل «الإدارة ← معمل التطوير ← جودة الدليل ودفعات الاستيراد». أصبحت مراجعة العينة `catalog-staging-20261021-2` بدل الأولى، ويتطلب تغيرها حكمًا جديدًا على التصميم. هذه أدوات المدير فقط؛ لا تستبدل شاشات الأعضاء ولا تغير الدليل أو التعاقدات أو التقييمات أو الأخبار أو العضويات ولا تنشئ إشعارات لهم.

أضيف **تصحيح الصف نفسه**، وربط صريح بمعرّف سجل قائم عند تأكد المدير، وإعادة فحص الدفعة، وتنزيل المقترحات المقبولة للمراجعة. لا يوجد زر تطبيق أو نشر أو دمج إلى دليل الإنتاج. يظل C07 جزئيًا إلى أن يجهز تطبيق دفعة إنتاج بمعاملات واستعادة معتمدة؛ لا يحول ملف JSON أو بصمته إلى أمر تنفيذ.

## رحلة التصحيح

1. افتح دفعة، ثم «تصحيح الصف» تحت الجهة. تظهر حقول الاسم والمعرّف والتخصص والعنوان والمركز والأرقام والمواعيد في نموذج داخل الصفحة. التخصص والمركز يقترحان قيم الدليل الحالي؛ قيمة جديدة هنا تخص الاقتراح ولا تضيف تصنيفًا إلى الإنتاج.
2. ترى القيمة الحالية في الدليل تحت الحقل عند ربط سجل قائم، وتظل القيم الأصلية للملف متاحة في قسم مستقل. تصحيح الهاتف يدوي عندما ينقص صفر أو خانة؛ لا يُخمّن رقم غير معلوم.
3. الخانة الفارغة تعني عدم اقتراح تعديل هذا الحقل. لا تمسح قيمة قائمة. المعرّف الفارغ يخص اقتراح جهة جديدة، وليس حذف الجهة القديمة.
4. تظهر الأسماء المشابهة مع العناوين والمعرّفات؛ يعرض التطابق في العنوان أولًا ضمن ثمانية اقتراحات مع العدد الإجمالي. «ربط بهذا السجل» يملأ المعرّف فقط، ثم يطلب تأكيد المدير لهوية الجهة. تغيير المعرّف أو إلغاء ربطه يرفضان دون التأكيد. الاسم وحده لا يثبت الهوية، ولا تُدمج فروع أو علاقات تعاقد تلقائيًا.
5. «حفظ التصحيح وإعادة الفحص» يحفظ داخل الدفعة الخاصة، ويعيد تحليل جميع صفوفها حتى يكشف التكرار الذي قد يسببه تعديل صف آخر. يحفظ الأصل الأول ولا يعيد كتابته.
6. كل صف تغيّر معناه أو لقطة مصدره يعود إلى انتظار القرار؛ الصفوف غير المتأثرة تحتفظ بقرارها. الصف الملتبس أو الناقص أو المكرر لا يقبل كصف سليم. تعرض الشاشة عدد الصفوف المتغيرة والقرارات المعادة للمراجعة.
7. «إعادة فحص الدفعة» تقارنها بالدليل وقت الطلب. الدفعات القديمة تحتاج هذه الخطوة قبل التحرير أو القرار أو التنزيل؛ يعود حكمها القديم إلى المراجعة، ولا يعتبر موافقة على المراجعة الجديدة.

إصدار الدفعة الذي فتح عليه نموذج التصحيح محفوظ معه. قرار أحدث في تبويب آخر يرفض الكتابة القديمة. إذا جرى تحديث الدفعات أثناء بقاء النموذج مفتوحًا، تبقى القيم التي كتبها المدير ظاهرة مع تعطيل الحفظ حتى يلغي التصحيح ويفتح النسخة الأحدث. لا تُستبدل قيمه بصمت ولا تتبنى المسودة نسخة أحدث دون مراجعة.

## التراجع وسلامة الأصل

يتضمن سجل التراجع القرارات والتصحيحات وإعادة الفحص، بحد 30 خطوة والسقف السابق لحجم مساحة المدير، دون إزاحة صامتة للقرارات القديمة. التراجع يعيد القيم السابقة في الدفعة ويعيد تحليلها مقابل قراءة المصدر الحالية. لا يعيد قبولًا سابقًا إذا لم تعد بصمته مطابقة، ولا يحيي قرارات إصدار قديم عبر التراجع في سجله. القيم الأصلية الأولى تبقى محفوظة طوال عمر الدفعة.

بصمة المصدر تشمل السجل المحدد وجميع الأسماء المطابقة في القسم، حتى ما تجاوز اقتراحات العرض الثمانية، مع القيم والإصدار وحالة الإخفاء والإيقاف والإدراج. تبقى هذه الحالات للعرض فقط ولا تستورد صلاحيات نشر أو أهلية أو تعاقد من الملف.

## ملفات المقترحات

- **JSON:** صفوف مقبولة فقط، ومرجع الدفعة، ومعرّف السجل الموجود أو اقتراح جديد بلا معرّف إنتاج، والقيم الحالية والمقترحة والفروق، وأرقام الاتصال المصنفة، ووقت الفحص ونسخة المساحة وبصمة المحتوى. لا سجل قرارات أو بيانات أعضاء أو نصوص تقييمات.
- **Excel CSV:** جدول مختصر للقيم المقترحة، والمحمول والأرضي والمختصر في أعمدة مستقلة. تستهل المعرّفات والأرقام بعلامة اقتباس نصية لحفظ الأصفار؛ قد تراها بعض برامج الجداول حرفيًا. JSON مرجع القيم الكامل. تُقتبس الخلايا وتهرّب علامات الاقتباس وتُحيّد بدايات معادلات الجداول حتى لو كانت آتية من قيمة قديمة في الدليل.
- يعاد التحقق من المدير وحالة المعاينة، ويقرأ المصدر مجددًا قبل تجهيز الملف. أي صف مقبول تغيرت بصمته يوقف التنزيل كله؛ يلزم إعادة الفحص والمراجعة. لا يُنزل ملف فارغ أو دفعة مستبعدة أو قديمة غير معاد فحصها. يتحقق المتصفح أيضًا من نسخة الدفعة قبل التنزيل، ويلغي الرد المتأخر بعد مغادرة الشاشة أو عند غيابها.
- هذه لقطة وقت تجهيز الملف وليست قفلًا مستمرًا على قاعدة الإنتاج، أو توقيع صلاحية يسمح بالتنفيذ لاحقًا. لا يمكن للخطة إثبات صحة رقم ميدانيًا أو سريان تعاقد لم تراجع مصادره.

الملفات مخصصة لمراجعة الإدارة، ولا تنشر في Git أو الأصول العامة. تحفظ حدود 4.18: خمس دفعات، و30 صفًا للدفعة، و700000 بايت للحالة، و32768 بايت للطلب، وآخر 40 معرف عملية، وقراءة الملفات محليًا. لا مزود ذكاء خارجي أو اتصال بالمقدم أو كتابة إلى MyNekaba.

## الجاهزية والتشغيل

لوحة الجاهزية بمراجعة `p0-readiness-20261021-3` تعرض عدد الدفعات القديمة المحتاجة إلى إعادة الفحص، وتستبعد قبولها التاريخي من عدد المقترحات الحالية المقبولة. التقارير أعداد فقط.

تحتاج هذه الإضافة الواجهة **4.19.0** والخلفية **`development-catalog-plans-v1`** إلى جانب قدرة الاستيراد الأولى. تأكد فحص الإنتاج في بداية المهمة من نشر `development-catalog-staging-v1`، ولا يستدل بذلك على نشر الإضافة الجديدة. لا توجد هوية Google متصلة ببيئة التنفيذ؛ ينشر المالك Firebase من Cloud Shell:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only origin main && bash scripts/deploy-medical.sh --existing-config
```

للفحص العام بعد نشر الخدمة، دون تسجيل دخول أو قراءة ملف خاص:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --require-catalog-plans --require-catalog-staging --require-service-workflow --require-development-lab --rayati --vercel
```

يمكن إيقاف العينة من المعمل دون حذف دفعات أو المساس بالدليل. يحتفظ الإصدار الجديد بالدفعات السابقة ويطلب إعادة فحصها صراحة. لا تعميم للأعضاء في هذه الحزمة، ولا تؤدي موافقة التصميم إلى تفعيله لهم.

## التحقق المطلوب والمُنفذ

تشمل اختبارات الوحدة والحماية: حفظ الأصل، وإبطال قبول الصف المعدل فقط والمتأثر بالتكرار، وتأكيد تغيير الهوية، وفحص جميع تطابقات المصدر، والتراجع بعد تغير المصدر، وترقية الدفعات القديمة دون إحياء موافقات قديمة، ورفض تجاوز الصلاحيات وتغيير نية إعادة الطلب، وحظر التنزيل القديم أو المتعارض أو الموقوف، وحماية CSV والأصفار.

رحلة المتصفح تتحقق من التصحيح والمعرّف وتعارض التبويبات والتنزيل الحقيقي وإعادة الفحص والتراجع، بمقاسات 320–1440 ودون نشر بيانات. اختبار Firestore Emulator يتحقق من إعادة التصحيح المتزامن وخطة المقترحات وثبات دليل الأعضاء وبيانات المصدر. يسجل تقرير التسليم نتيجة الفحوص بعد اكتمالها؛ وجود وصف الاختبار وحده لا يعني نجاحه.

نتيجة التحقق المحلي في 21 أكتوبر 2026: **183 اختبار وحدة وحماية ناجحًا**، ورحلة المتصفح الكاملة ناجحة دون أخطاء تشغيل، واختبار Firestore Emulator ناجح، والبناء وفحص الأصول ناجحان. اختبرت رحلة الهاتف والحاسب التصحيح وتأكيد المعرّف وتعارض التبويبات وتنزيل الملفين وإعادة الفحص والتراجع، مع ثبات دليل الأعضاء ومصدر العضوية. هذه نتائج اختبار محلي ومحاكي، وليست تسجيل دخول إنتاج أو نشر Firebase من هذه البيئة.
