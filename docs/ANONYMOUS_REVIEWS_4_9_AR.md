# التقييم الإجمالي وعناصر الخدمة وتجارب الأعضاء — 4.9.0

## العرض للأعضاء

من بطاقة الطبيب أو المستشفى أو المركز أو المعمل أو الصيدلية اضغط «تفاصيل التقييم وآراء الأعضاء». تظهر الدرجة الإجمالية وعدد التقييمات المنشورة، ومتوسط الاستقبال والتعامل ووقت الانتظار والنظافة وتنظيم الخدمة. لكل عنصر عدد مشاركات مستقل؛ عدم التقييم لا يحسب صفرًا، وتظهر «لم يُقيّم بعد» عند غياب درجاته. المتوسط الإجمالي هو متوسط نجمة الزيارة التي اختارها الأعضاء، وليس متوسط العناصر الفرعية.

الدرجات القديمة المنشورة تدخل الحساب إذا كانت عناصرها مسجلة؛ لا تحتاج إعادة إدخال. لا تخمن عناصر للتقييم القديم الذي لم يسجلها. الطبيب له تقييمه عبر مقاره كما في الهوية القائمة، بينما تستخدم المعامل والصيدليات سياسة توحيد الفرع الحالي، دون جمع فروع جغرافية مختلفة أو التبرع ببيانات فرع مخفي.

## الملاحظات والخصوصية

طلب المالك إظهار الملاحظات للأعضاء دون اسم، مع إبقاء الاسم للإدارة. كانت السياسة المعروضة للأعضاء سابقًا تعتبر التعليقات خاصة؛ لذلك لا نحول ملاحظاتهم القديمة إلى منشورات بأثر رجعي. يوجد اختيار صريح غير محدد افتراضيًا: «أوافق على عرض ملاحظتي للأعضاء دون اسمي بعد مراجعتها». يستطيع صاحب تقييم قديم اختياره من تعديل تقييمه، ويعاد للمراجعة.

ما لم يختر العضو المشاركة تبقى الملاحظة له وللإدارة. الإدارة ترى الاسم والملاحظة وحالة المشاركة، ولا تستطيع اختيار المشاركة بدل الكاتب أو تعديل نصه. عند اعتماد ملاحظة اختار صاحبها مشاركتها يلزم تأكيد المراجع خلو النص من بيانات شخصية أو صحية. يرفض الخادم الاعتماد دون التأكيد. يمكن إخفاء التقييم كالسابق؛ لا تُنشأ صلاحية تحرير نص العضو للإدارة.

مسار القراءة المجهول يعيد حقولًا محددة فقط لكل ملاحظة: النص والدرجة والعناصر؛ لا يعيد اسمًا أو رقم عضوية أو كود عامل أو هوية صاحبها أو معرف التقييم أو رابطًا لحسابه، حتى عند طلبه بحساب مدير. تبقى أسماء أصحاب التقييم في مسار الإدارة الخاص. يعرض حساب العضو «تقييمك» بدل الاسم في قائمة تقييماته.

يحجب النص المنشور آليًا الاسم المسجل المحفوظ مع التقييم عند تطابقه حرفيًا، والبريد والأرقام الطويلة، لكن ذلك ليس ضمانًا لإزالة كل التفاصيل التعريفية من نص حر. قد يكتب صاحب الملاحظة اسمًا مختلفًا أو وصفًا صحيًا؛ لذلك تلزم المراجعة البشرية، ويحذر النموذج من إدخال هذه البيانات. العرض «دون اسم» يعني عدم ربطه بهوية الحساب، ولا يوصف بإخفاء هوية مطلق.

إلغاء اختيار المشاركة أو تعديل المحتوى يعيد النسخة للمراجعة، ويسحبها من الطلبات الجديدة فور الحفظ. لم تتغير حماية النسخ أو الاعتماد مرة واحدة أو عدم إعادة مراجعة حفظ مطابق. صفحة مفتوحة لدى قارئ آخر تحتاج «تحديث التقييمات» أو إعادة الفتح لرؤية السحب؛ لا يمكن سحب نسخة قرأها أو صورها سابقًا.

## حسابات وحدود الخدمة

الخادم يراجع جلسة فعالة وظهور الجهة قبل قراءة تقييماتها. المسودات والمخفي والتقييم الأحدث المعلق لا يسمحون بإحياء نسخة أقدم منشورة لصاحبها عبر سجل مكرر. جلب التفاصيل عند الطلب فقط، وليس مع كل بطاقة أو كجزء من تنزيل الدليل. لا تحفظ الردود في localStorage أو Service Worker، وCache-Control الخاص بالخدمة no-store.

تجزئة التعليقات إلى 20 في الصفحة، مع السابق والتالي. الإحصاءات تحسب جميع تجارب الجهة المعتمدة ذات الصلة؛ لكل طلب حد 60 في 15 دقيقة للجلسة. استعلام Firestore يستخدم target_id فقط مع إسقاط حقول محددة، ولا يحتاج فهرسًا مركبًا جديدًا. لا يستدعي قاعدة العضوية إلا للتحقق المعتاد للقراءة فقط. لا يُضاف تتبع للمستخدمين أو إشعارات خارجية.

تجميع تفاصيل جهة كثيرة المراجعات يقرأ سجلاتها عند الطلب؛ يلزم لاحقًا تجميع معاملات مسبق ومؤشر صفحات ثابت عند أحجام كبيرة، مع الحفاظ على سحب الموافقات فورًا. التقسيم الحالي بالصفحة قد يتغير بين طلبين إذا أضيفت/سحبت تقييمات، وليس لقطة أرشيفية ثابتة. لا تدعي هذه الحزمة اختبار تحمل إنتاج.

## التفعيل

الواجهة 4.9.0 تتعرف على publicReviewDetails في الدليل. الخدمة الجديدة تعلن **public-review-details-v1**. الخدمة القديمة تستمر بالنجوم السابقة دون إظهار زر مشاركة لا تستطيع حفظه. لا تكفي استضافة Vercel؛ يلزم نشر Medical Firebase من حساب المالك:

```sh
cd ~/cloudshell_open/Medical
git pull --ff-only
bash scripts/deploy-medical.sh --existing-config
```

فحص عام بعده:

```sh
node scripts/check-live.mjs --rayati --require-public-reviews
```

هذا ينشر أيضًا حزمة المحتوى السابقة إذا لم تكن فعّلت. لا ينشر المساعد ملاحظات حقيقية ولا يقرأها في اختبارات الإنتاج؛ الاختبارات المحلية فقط ببيانات مصطنعة. تفاصيل الخلفية في BACKEND_SETUP_AR.md، والمصدر MyNekaba بلا أي كتابة.

## نتيجة التحقق المحلي

نجحت 110 اختبارات، واختبار المتصفح الكامل دون أخطاء تشغيل مع مشاركة ملاحظة قديمة صراحة، والتأكد من ظهور الاسم للإدارة دون مسار العضو، واعتماد النص بعد التأكيد، وإلغاء المشاركة، وعرض الدرجات دون تنفيذ HTML داخل التعليق. نجح اختبار Firestore الحقيقي بالمحاكي لإسقاط الحقول وحفظ اختيار المشاركة وسحبه. هذه بيانات مصطنعة وليست قراءة لتقييمات الزملاء أو نشرها. إعادة نفس اعتماد النسخة المنشورة تبقى عملية بلا تغيير حتى دون إرسال التأكيد مرة أخرى.
