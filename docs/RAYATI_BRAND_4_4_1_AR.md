## إثبات النشر وخطوة النطاق

نُشر الالتزام `51cdcd1` بنجاح على Vercel، ونجح فحص GitHub Validate Medical رقم `39167398240` بعدما كان فحص المالك السابق يفشل بسبب الاسم. طابقت الصفحة والـmanifest وapp وrelease وService Worker والأيقونة وصورة المشاركة ناتج البناء بايتًا ببايت، وفُتحت صفحة الدخول على 390×844 بالاسم والشعار الجديدين دون تجاوز عرض الشاشة.

أكد المالك أنه يريد **بطاقة المشاركة وتغيير عنوان النطاق معًا**. الرابط المقترح `https://rayati-we.vercel.app/`. ينبغي أولًا إضافته عبر إعدادات مشروع Vercel نفسه مع إبقاء النطاق الحالي. لا يُضاف تلقائيًا إلى قائمة الإنتاج الثابتة قبل تأكيد ربطه؛ helper الموجود يدعم نطاقًا إضافيًا مضبوطًا صراحة ويحتفظ بالنطاقات السابقة.

بعد أن يضيفه المالك وتُؤكد استجابته بهوية رعايتي الصحيحة، يُشغَّل داخل Cloud Shell المسجل بالمشروع:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only && MEDICAL_ALLOWED_ORIGINS=https://rayati-we.vercel.app bash scripts/deploy-medical.sh --existing-config
```

المساعد يحتفظ بالنطاقات القديمة، وينشر مشروع Medical فقط ثم يتحقق من OPTIONS لكل النطاقات. لا يعدل MyNekaba. التحقق المستقل بعد النشر:

```bash
node scripts/check-live.mjs --vercel --rayati
```

لم يُنفّذ ربط النطاق أو نشر السماح من هذه الجلسة لغياب اتصال Vercel وهوية Google. لا يعني نجاح نشر الواجهة أن العنوان الجديد أصبح فعالًا أو أن CORS تفعّل. بعد تفعيل الخطوتين نراجع رابط الإنتاج الجديد ونجعل بيانات og:url وog:image تشير إليه، ثم نختبر الدخول قبل توزيعه.
