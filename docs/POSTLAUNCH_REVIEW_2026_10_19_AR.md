# تقرير التشغيل الأولي بعد مشاركة رعايتي مع الزملاء

19 أكتوبر 2026 — نطاق التقرير: إفادة المالك، سجل الإصلاحات، وفحوص HTTP عامة للخدمة المنشورة. لا يتضمن بيانات أعضاء أو تعليقات حقيقية.

## الحكم

انتقل التطبيق إلى الاستخدام الفعلي وفق تأكيد المالك بوجود تفاعل من الزملاء. هذه نتيجة إيجابية للإطلاق الأولي، لكنها لا تثبت نسبة نجاح أو رضا معينة. الاستمرار بإطلاق تدريجي مع متابعة يومية مناسب؛ التوسع يتطلب قياسًا فعليًا لجودة البيانات والرحلات الأكثر استخدامًا.

## ما ثبت وما لم يثبت

| البند | الدليل وحدوده |
|---|---|
| الوصول للزملاء ووجود تفاعل | إفادة المالك في المحادثة؛ لا يوجد عدد مستخدمين مثبت |
| صحة خدمة Medical وربط نطاق رعايتي | فحص عام: الصحة 200، CORS للنطاق المعتمد، ورفض الدليل دون جلسة 401 |
| حماية الأصل | الطلب من أصل غير معتمد مرفوض 403؛ لا يعد ذلك تدقيق اختراق شاملًا |
| إصلاح الخروج أثناء العمل | الصحة الحية تعلن admin-idle-v1؛ يثبت نشر الخدمة الجديدة، ولا يغني عن متابعة تجربة المدير الفعلية |
| عمل الدخول والتقييم سابقًا | أكده المالك في التجارب السابقة؛ لا نساوي ذلك بقياس شامل لكل الزملاء بعد الإطلاق |
| عدد الزيارات، البحث، التقييمات والاحتفاظ | غير متاح للمساعد؛ لا توجد في هذا التقرير قراءة لسجلات الأعضاء أو لوحة تحليلات فعلية |
| توقع 300 مستخدم | تقدير قبل الإطلاق، وليس عددًا تحقق |
| أوقات الاستجابة | الفحص عينة لحظية، وليس متوسطًا أو مئينًا لإنتاج المستخدمين |

فحوص النشر الآلية السابقة ناجحة. مسار Firebase في GitHub يمكن أن ينجح في فحص الجاهزية مع تخطي النشر؛ إثبات نشر جلسات الخمول هنا مصدره قدرة الخدمة الحية، لا اللون الأخضر وحده.

## ما عولج استجابة لملاحظات المالك

- النص null في تفاصيل الفروع، وظهور بعض تصنيفات الجهات في غير قسمها.
- إزاحة إدارة الموبايل، وفلترة السجلات، وحماية التعديل والرجوع لسياق البحث.
- فصل تغيير التصنيف عن الهوية الأصلية للجهة وتقييماتها.
- جلسة المدير حسب الخمول بدل الانتهاء المطلق أثناء إدخال البيانات.
- حزمة 4.8.0 التالية تنظم التعليمات والأخبار والنشرات؛ تُراجع حالة نشرها في وثيقة الحزمة، ولا تعد ميزة حية بمجرد ذكرها هنا.

هذه ملاحظات نقلها المالك؛ لا ننسبها إلى بلاغات زملاء محددين أو ندعي أنها صادرة من نظام تتبع آلي.

## أولويات أسبوع الاستخدام الأول

1. سجل يومي مجهّل للمشكلة، نوع الجهاز، الرحلة، وهل تكررت؛ دون كود عامل أو موبايل أو هوية أو نص بحث شخصي.
2. تجربة قصيرة مع 5–10 زملاء: الدخول، الوصول لجهة مناسبة، الاتصال/الخريطة، قراءة تعليمات، إرسال تقييم. يسجل إنجاز كل مهمة والوقت والعائق بعد موافقتهم، دون جمع بيانات تحققهم.
3. مراجعة صحة تعاقدات وأرقام الجهات الأعلى طلبًا، وتسجيل مصدر وتاريخ التحقق. لا ننشئ مواعيد أو نسب تحمل بالتخمين.
4. مراجعة أخطاء Cloud Run والحدود والاستهلاك والفوترة من حساب المالك. إعداد تنبيه ميزانية وتجربة استعادة نسخة Medical إذا لم يثبتا تشغيليًا.
5. اعتماد تعليمات الشركة قبل نشرها، وتسمية مسؤول مراجعتها، وتاريخ انتهاء الأخبار المؤقتة. لا تتحول تعديلات العناوين الإدارية إلى أخبار للأعضاء.

## القياس المقترح، وليس المنفذ

أعداد يومية مجمعة لنجاح/فشل الدخول دون المدخلات، وفشل API حسب رمز عام، ونجاح الوصول للاتصال والخريطة، ونسبة البحث دون نتائج دون حفظ نصه، والتقييمات المعلقة وزمن اعتمادها. يبدأ تنفيذها بسياسة احتفاظ وحدود تكلفة وشرح خصوصية محدّث؛ لم تُضف أدوات تتبع خارجية أو معرفات إعلانية في هذه الحزمة.

القرار: نتابع الاستخدام الحقيقي ونصلح العوائق المثبتة أولًا؛ لا نعطي التطبيق درجة 70% أو 100% بلا عينة وقياس. المرجع التالي [مركز إدارة المحتوى](CONTENT_STUDIO_4_8_AR.md).
