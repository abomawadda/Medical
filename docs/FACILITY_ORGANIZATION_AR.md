# تنظيم الجهات والفروع والشبكات — الإصدار 4.2.0

تنفيذ طلب المالك بعد اعتماد خطة إزالة التكرار في 18 أكتوبر 2026. النطاق الحالي الصيدليات ومعامل التحاليل، مع إبقاء بقية أنواع الجهات ومنظومة العضوية دون تغيير.

## النموذج والقرارات

الجهة ← فروع فعلية ← سجلات تعاقد/شبكات لكل فرع. يجمع اسم السلسلة فروعها في بطاقة واحدة، ولا يعني ذلك أن كل فروعها متعاقدة؛ المعروض فقط ما سمحت به استجابة الدليل المحمية. يظل العنوان المختلف فرعًا مستقلاً. اختيار شبكة معينة يرشح النتائج، ويظهر رابط جميع الفروع عندما تستبعد التصفية فروعًا أخرى.

يظهر الفرع المتطابق مرة واحدة، وتظهر شبكاته مجتمعة. عند اختلاف معلومات الموظفين والأسر، توجد أزرار للشبكة داخل البطاقة لعرض عنوانها واتصالاتها من سجلها الأصلي؛ لا نخلط رقم هاتف خاصًا بعلاقة تعاقد مع علاقة أخرى. تحفظ علاقة الأسر المستوردة سابقًا أيضًا، ولا نستنتج نسب تحمل أو مواعيد أو تعاقدًا من الاسم أو الهاتف.

التجميع **غير متلف**: لا يحذف صفوف المصدر أو وثائق Medical، ولا يبدل معرفات الجهات أو مصادر Excel أو تقييمات الأعضاء. الواجهة تقدم بطاقة فرع موحدة فوق السجلات، بينما يظل جدول الإدارة يعرض كل سجل مصدر لإمكان مراجعته وإخفائه وإيقافه بصورة مستقلة. الرجوع ممكن بإزالة ربط الفرع من السياسة وإعادة نشر الكود، دون استعادة بيانات محذوفة.

## ما لم يُدمج

- اسم المختبر أو البرج مع مدينة واحدة لا يكفي لدمج كل فروع المدينة.
- الخطوط الساخنة مشتركة بين فروع السلاسل، وحتى المحمول قد يخص إدارة عدة فروع؛ الهاتف وحده لا يثبت الهوية.
- البرج بالسنبلاوين: برج النيل/بنك مصر مقابل برج النمس/بنك القاهرة — اختلاف يحتاج مراجعة.
- المختبر بدكرنس: برج الأمراء قرب البنك الأهلي مقابل برج التحرير/مركز الشرطة — يبقيان فرعين.
- العزبي بالجمهورية: أبو طارق في سجل الموظفين مقابل أبو طوق في الأسر — لم نغيّر اسم البرج بالتخمين.
- صيدليات محمد الدنف مقابل أورانج ذات أرقام متشابهة أو مشتركة — اختلاف الأسماء/العناوين لا يُحسم بالهاتف.

التقرير القابل للتجديد `docs/FACILITY_DUPLICATES_2026_10_18.json` يتضمن 8 أزواج تشابه تحتاج فحصًا و171 زوجًا يشترك في اسم السلسلة/المركز فقط؛ العدد الأخير **ليس عدد أخطاء أو تكرارات مؤكدة**. يشمل التقرير الأساسي الجهات المحجوبة كذلك للتدقيق، ولا يعيد نشرها للأعضاء.

```bash
node scripts/audit-facility-duplicates.mjs --report docs/FACILITY_DUPLICATES_2026_10_18.json
```

## الإدارة والوقاية

زر «الفروع والتكرار» يعرض الفروع المجمعة وسجلات مصادرها والاقتراحات التي لم تُدمج، مع فتح السجل للتحرير. في نموذج صيدلية أو معمل جديد يظهر تحذير عند تشابه الاسم والعنوان في المركز نفسه، مع خيار تعديل الموجود. لا يُحفظ إدخال مشابه جديد دون إقرار المدير أنه فرع مختلف. التحذير مساعدة إدخال وليس قيد صلاحيات جديدًا على المدير؛ لا يحوّل الترشيح التقريبي إلى هوية معتمدة.

تحرير سجل المصدر يحدّث الدليل كالمعتاد ويظل صامتًا للأعضاء؛ لم يُنشأ خبر تلقائي من الدمج. يمكن للإدارة نشر إعلان مستقل بالسياسة السابقة. شاشة دمج يدوي عامة أو استيراد وتراجع دفعات من داخل الواجهة مرحلة لاحقة؛ سياسة الروابط الحالية موثقة ومراجعة في Git ولا تقبل علامة ربط مزورة من طلب العميل.

## التقييمات والروابط والمفضلة

- كل رابط قديم يفتح الفرع ضمن الجهة الموحدة. المفضلة المحفوظة بمعرف قديم تستعيد نفس الفرع، وإلغاء حفظه يمسح معرّفاته البديلة المتاحة على الجهاز حتى لا يبقى مفضلًا خفيًا.
- بعد نشر Firebase `facility-branches-v1`، إحصاء الفرع يجمع **أحدث تجربة لكل عضو** عبر المعرفات المرتبطة (وقت التحديث، ثم ترتيب معرف ثابت عند تساوي الوقت)؛ لا يجمع أعدادًا أو متوسطات جاهزة قد تحتوي نفس الكاتب مرتين. أحدث نسخة معلقة/مخفية تستبعد النسخة المنشورة الأقدم لنفس الكاتب.
- حفظ العضو من أي معرف بديل يبحث عن تقييماته المعروفة بمعرفات خادمية محددة داخل معاملة، ويعدل الأحدث الموجود بمعرفه وتاريخ إنشائه. لا ينشئ تقييمًا ثانيًا لنفس الفرع. التبديل بين معرفي الموظفين والأسر دون تغيير التجربة لا يعيد الاعتماد.
- السجلات التاريخية المكررة تبقى في Medical؛ تعرض قوائم العضو ومراجعة المدير أحدثها فقط. لا يعتمد المدير سجلًا أقدم إذا وُجد للكاتب نفسه سجل أحدث لنفس الفرع؛ تظل صلاحية الكاتب ومراجعة النسخة وعدم تكرار القرار نافذة.
- مصدر الإحصاء الخاص يقرأ حقول الحساب اللازمة فقط، دون التعليقات، ويعيد أعدادًا ومتوسطات فقط. ذاكرة تجميع مؤقتة حتى 30 ثانية لكل مجموعة صلاحيات، تُفرغ بعد معاملات الحفظ والمراجعة في النسخة نفسها؛ قد يظهر تأخر حتى 30 ثانية بين نسخ التشغيل المختلفة. لا توجد كتابة أو ترحيل شامل عند فتح الدليل.
- مع الخدمة القديمة تستمر البطاقات الموحدة والروابط، وتُعرض درجات مصدر الشبكة المحدد كما كانت؛ لا تدعي الواجهة متوسطًا موحدًا بحساب غير موثوق. يتبقى نشر الخدمة لتفعيل ضمان عدم التقييم المكرر والإحصاء الموحد على الإنتاج.

## التفعيل والتحقق

تنشر الواجهة عبر Vercel وPages. يتطلب توحيد التقييمات قدرة Firebase الجديدة، ولا تثبت نجاحات نشر الواجهة تفعيلها. من Cloud Shell للمالك:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only && bash scripts/deploy-medical.sh --existing-config
```

التحقق العام، دون بيانات دخول:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --vercel --require-facility-branches
```

MyNekaba للقراءة فقط. لا تنقل هذه الحزمة بيانات أعضاء أو كلمات مرور إلى Git أو الواجهة، ولا تغير مشروع النقابة أو قواعده أو حساباته.
