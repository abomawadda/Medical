## مكان المعاينة

الإدارة ← معمل التطوير ← **البدائل والمتابعة ومشواري** أو **إجراءات الشركة والطلبات والمواعيد**. يظل القديم هو مسار العضو. النماذج الخمسة السابقة محفوظة بمراجعاتها، والمعاينتان الجديدتان مستقلتان بقرار مراجعة جديد:

| المعاينة | المراحل | المراجعة المشتركة | الجمهور |
|---|---|---|---|
| `care_companion` | P3 / P6 | `p3-p6-20261021-1` | مدير مصرح به فقط |
| `service_planning` | P4 / P5 | `p4-p5-20261021-1` | مدير مصرح به فقط |

اعتماد التصميم لا يفعّل الميزات للأعضاء ولا يساوي اعتماد إجراء للشركة. لا يوجد زر تعميم في هذا الإصدار. نشر الواجهة المشتركة ورقم الإصدار لا يمنح العضو هذه الخدمات.

## ما يمكن تجربته

- **البدائل والمقارنة:** اختيار شبكة ومركز وبحث موحد، ثم مقر من الدليل المنشور. البدائل لنفس التصنيف والتخصص والشبكة والمركز، مع توسيع اختياري للمراكز الأخرى. يستبعد الموقوف ونفس مقدم الخدمة بفروعه. تقارن حتى ثلاث جهات داخل نفس الشبكة والتصنيف والتخصص، مع العنوان والمواعيد والهواتف المنفصلة والتقييم المنشور إن وجد؛ لا استنتاج لتساوي التغطية أو الأفضلية الطبية.
- **المتابعة:** يحفظ المدير اختياره في مساحته. «افحص تغييرات الدليل» يقارن بصمات الاسم والعنوان والاتصال والمواعيد والحالة والشبكة وإتاحة المقر بما كان عند المتابعة. لا تسجل أول متابعة خبرًا، ولا يسجل حفظ رقم النسخة وحده تغييرًا. الفحص يدوي، وليس مراقبة آنية أو مهمة مجدولة. التنبيه حقيقي فقط إن رصد فرقًا؛ محاكاة تغير المواعيد عليها شارة صريحة ولا تغير الجهة. القراءة خاصة بصاحب المساحة، ولا Push أو إرسال خارجي أو إشعار عضو.
- **الأقرب:** إضافة دبوس معاينة يدويًا من بطاقة المقر، مع رابط مصدر HTTPS وتاريخ حقيقي غير مستقبلي وتأكيد المطابقة. إحداثيات مصر فقط؛ ليست إحداثيات معتمدة للأعضاء. دون دبوس صالح لا يطلب موقع الجهاز. الموقع اختياري ومحلي في ذاكرة الشاشة، يمسح عند إخفائها أو تركها؛ رفض الإذن يبقي البحث بالمركز متاحًا. المسافة خط مستقيم وليست وقت قيادة أو إثبات صحة الدبوس.
- **مشواري:** حتى ست محطات يختارها المدير بنفسه داخل شبكة واحدة، مع التقديم والتأخير والإزالة. يجب أن تكون جميع المحطات منشورة ومتاحة ولها عنوان محدد قبل فتح خرائط Google. العنوان المركب يحتاج اختيارًا صريحًا من العناوين المسجلة؛ لا إحداثيات مخمنة أو موقع جهاز مرسل، ولا اقتراح علاج أو فحوص أو حساب زمن رحلة.
- **الملخص وملاحظات الوصول:** أعداد مساحة الإدارة فقط: المتابعة، والفروق المرصودة هذا الشهر، وأمثلة التنبيه، والأمثلة المحفوظة من «لم أجد». يفصل المرصود عن المحاكاة؛ ليست إحصاءات أعضاء أو نتائج طبية. الملاحظات من أسباب وشبكات ومراكز وتخصصات محددة، دون نص بحث خام أو حقل حالة صحية. لا يقدم عدادًا وهميًا لإنجازات الشبكة.
- **مسودات الإجراءات:** إنشاء وتحرير ونسخ وأرشفة مسودات إجراء أو مساعدة أو موافقة أو تحويل أو طلب موعد، مع الشبكة ومرجع المصدر/رابطه وتاريخه والجهة المصدرة والمسؤول والخطوات. «جاهزة للمراجعة» تتطلب اكتمال هذه الحقول؛ لا تعني اعتمادًا فعليًا. المحتوى الذي استُخدم في مثال لا يُستبدل: ينسخ لمراجعة جديدة، ويمكن أرشفة القديم مع إبقاء مرجع الحالات السابقة.
- **الطلبات والمواعيد:** أمثلة بلا أسماء أو تشخيصات أو مرفقات، من مسودة جاهزة فقط. جديد ← فحص ← استكمال/عودة للفحص ← انتهاء اختبار أو استبعاد؛ سجل للانتقالات ورفض القفز أو تغيير الحالة النهائية. لا يوجد تأكيد حجز أو موافقة أو إرسال لمستشفى. `bookingConnected` و`bookingConfirmed` ثابتان false.

تُكتب مصادر الإجراءات الفعلية بواسطة المدير؛ لا تملأ الواجهة لوائح الشركة أو نسب تحمل أو إجازات أو مواعيد من افتراضات. الحقول الحرة مخصصة لنصوص الإجراءات ومراجعها؛ لا تدخل فيها بيانات أعضاء أو أسرار أو ملفات صحية.

## الحفظ والصلاحيات

- GET/PATCH `/v1/admin/lab/workspaces/:id` وجلب المعاينة يتحققان من المدير الحي في كل طلب؛ رفض الزائر والعضو وتغيير الدور في المتصفح. الردود `no-store`، ولا صلاحية عبر الرابط.
- `medical_lab_workspaces/<feature>_<sha256(sourceAccountId)>` داخل Medical فقط، والمالك يؤخذ من الجلسة، لا من جسم الطلب. لكل مدير مساحة مستقلة، ولا تُكشف معرفات حسابه داخل العرض العام. قواعد Firestore لا تسمح للعميل بالوصول المباشر.
- حفظ ذري مع رقم نسخة متوقع، ومعرف عملية ثابت وإثبات نيتها. تكرار نفس العملية لا يكرر الحالة؛ تغيير النية أو قرار قديم يرفض. يعاد فحص إيقاف الميزة داخل المعاملة نفسها. تدقيق خاص يحفظ الإجراء والمعاينة والنسخة والفاعل والتاريخ، دون نسخ نصوص الإجراءات إلى سجل التدقيق.
- عند انقطاع رد الحفظ يحتفظ المتصفح بالعملية في ذاكرة الجلسة ويعرض «إعادة إرسال العملية السابقة» بنفس المعرف والقيم؛ يمنع عملية جديدة حتى حسم السابقة. لا يخزن نص البحث أو المسودات في localStorage، ويمسح السياق بتغيير الهوية والخروج. التحديث الكامل للصفحة لا يحافظ على ذاكرة عملية معلقة؛ يُراجع المدير الحالة المحفوظة أولًا.
- حد كل مساحة: 40 متابعة و40 دبوسًا و6 محطات، وآخر 50 تنبيهًا و50 مثال ملاحظة، و30 مسودة و50 حالة و20 انتقالًا للحالة و40 معرف عملية حفظ. لا تزاح حالات أو مسودات مفتوحة لتفريغ المساحة. هذه حدود اختبار، وليست سياسة احتفاظ لخدمة أعضاء مستقبلية.
- ينزل الدليل المنشور فقط؛ المخفي والمسودات غير متاحة. الدليل لقطة وقت التحميل؛ «تحديث البيانات» يجلبها مجددًا. فحص صلاحية/حالة خفيف كل 20 ثانية وعند العودة للتبويب، لا ينزل الدليل أو يمدد جلسة المدير. الإيقاف أو فقد الاتصال أو الصلاحية يمسح المحتوى المعروض. لا يستطيع مفتاح الإيقاف محو ملفات سبق تنزيلها.
- لا كتابة إلى الدليل والتقييمات والأخبار وإشعارات الأعضاء أو MyNekaba. لا يستخدم قارئ العضوية للكتابة.

## المتبقي قبل خدمات حقيقية

| المرحلة | المنجز الخاص | التبعية المتبقية |
|---|---|---|
| P0/P1 | معمل محمي، نماذج وتصميم ودليل مترابط | حكم وتفعيل مستقل للأعضاء؛ لوحة التعميم لم تنفذ |
| P2 | زيارة من بيانات فعلية وبلاغات أمثلة | استقبال بلاغ عضو ومسؤول فحص ورد فعلي وسياسة احتفاظ |
| P3 | بدائل ومقارنة ومتابعة ودبابيس وموقع اختياري | اعتماد إحداثيات وربط تغييرات الأعضاء وصلاحيات وتفعيل مستقل |
| P4 | مصدر وخطوات ومسؤول ومسودة وتجارب مسار طلب | شرح الشركة ولوائحها وسريانها وصاحب القرار وزمن الخدمة والخصوصية |
| P5 | تجربة واضحة لطلب موعد دون تأكيد | اتفاق أو API مع مقدم الخدمة وتوفر فعلي وسياسة إلغاء قبل أي حجز |
| P6 | مشوار وملخص أمثلة وتغذية راجعة | بيانات مجمعة فعلية ومعايير تقارير وإشعارات ثم قرار التعميم |

لم تكتمل خدمات الإنتاج في كل المراحل بهذا الإصدار؛ اكتمل تجهيز هذه الأجزاء للمعاينة بحسب تبعياتها المتاحة. لا تساوي أعداد المعمل استخدام المستخدمين ولا تثبت نجاح خدمة طبية.

## التحقق والتشغيل والرجوع

الاختبارات تغطي عزل المديرين، ورفض العضو والزائر، وتعارض الحفظ وتكراره وإيقاف الميزة أثناء المعاملة، والفروق الفعلية والمحاكاة، والشبكات والبدائل والفروع والمشوار، والمصدر والتاريخ والطلبات النهائية، ورفض تأكيد حجز. يشمل المتصفح رحلة الحفظ وإعادة إرسال رد مفقود دون تكرار، ورفض الموقع، وغياب إرسال إحداثيات الجهاز، وقياسات 320/390/768/1440، وصورًا ببيانات الاختبار فقط. اختبارات SDK في Firestore Emulator تستخدم بيانات عضوية مصطنعة وتثبت بقاء المصدر والدليل كما كانا.

يتطلب الإصدار قدرة `development-roadmap-v1` إضافة إلى القدرات السابقة. أمر جلسة Cloud Shell المخولة:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only origin main && bash scripts/deploy-medical.sh --existing-config
```

وفحص الخدمة بعد النشر:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --require-roadmap-preview --require-visit-preview --require-directory-preview --require-development-lab --vercel
```

لا يثبت نجاح Vercel أو CI إتمام نشر Firebase. سجل التحقق الفعلي النهائي يميز كلًا منهما. تبقى المعاينات السابقة متاحة حسب قدرات الخدمة الحالية، وتظهر رسالة تحديث حين تكون الخلفية أقدم.

للرجوع: إيقاف المعاينة المعنية من «الملاحظات والقرار» يعطل جلبها وحفظها، ويحفظ بيانات الاختبار ولا يحذفها. لا توجد واجهة عضو جديدة لإرجاعها؛ يبقى مساره القائم. إعادة تفعيل المعاينة لا تنشرها للأعضاء ولا ترث قرار اعتماد لنسخة تصميم أخرى.


نجح التحقق المحلي للإصدار: **153 اختبار وحدة وحماية**، والبناء وفحص الأصول، ورحلة المتصفح كاملة بأربعة عروض دون أخطاء JavaScript، وFirestore Emulator باستخدام SDK الفعلي. الأدلة المحلية في `/workspace/medical-deliverables/roadmap-4160/`، دون بيانات إنتاج خاصة. أكد فحص الإنتاج قبل رفع الإصدار إتاحة `development-visit-v1` وعدم إتاحة `development-roadmap-v1` بعد؛ لا تُعلن المعاينتان الجديدتان متاحتين على Firebase حتى نجاح نشر الخدمة وفحص قدرتها.
