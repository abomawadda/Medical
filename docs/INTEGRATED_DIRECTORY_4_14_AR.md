# تجربة الدليل المترابطة — رعايتي 4.14.0

19 أكتوبر 2026 — استكمال وظيفي خاص ضمن P1، وفق [الاتفاقية](../APP_AGREEMENT_AR.md) و[الخارطة المرحلية](PHASED_PREVIEW_ROADMAP_AR.md).

## مكان التجربة ونطاقها

**الإدارة ← معمل التطوير ← تجربة الدليل المترابطة ← فتح المعاينة**. الواجهة الجديدة تستخدم الدليل المنشور فعليًا بدل البيانات التوضيحية. تبقى النماذج الثلاثة السابقة كما راجعها المالك، ولا تنقل موافقتها للرحلة الجديدة. معرفها `directory_experience` ومراجعتها المشتركة بين الواجهة والخدمة `p1-directory-20261019-1`.

المعاينة خاصة بالمدير، للقراءة فقط، وجمهورها ثابت خادميًا. لا يوجد زر تعميم للأعضاء في هذا الإصدار. لا تتغير الرئيسية أو التقييمات أو البيانات الأصلية لدى العضو. شعار التطبيق وألوان WE وCairo/Tajawal والرسوم التعبيرية الحالية محفوظة.

## ما يمكن تجربته

1. ابحث من الرئيسية عن طبيب أو جهة أو تخصص أو منطقة في جميع أقسام الدليل. الأقسام: الأطباء والمستشفيات والمراكز والصيدليات والتحاليل والأشعة. مراكز الأسنان تظهر بتخصص الأسنان، وتصنيف المستشفى أو المركز يحترم تعديل الإدارة المسجل.
2. صفّ حسب شبكة المستفيدين والمركز والتخصص؛ تظهر عوامل البحث النشطة ويمكن مسحها. تبديل القسم يمسح البحث والمركز والتخصص السابقين، ويبقي اختيار الشبكة ظاهرًا. «كل التخصصات» تنقل لقائمة مستقلة.
3. افتح البطاقة المختصرة ثم اختر المقر من أزرار واضحة. هوية الطبيب وفروع الجهات تعتمد بيانات الربط الحالية؛ لا تُدمج أسماء متشابهة تخمينًا. قد تختلف شبكة المستفيدين والاتصال والعنوان بين المقار.
4. استخدم تبويبات التفاصيل والفروع وتجارب الأعضاء. المحمول والأرضي والمختصر مجموعات مستقلة. رقم استقبال المستشفى البديل لا يقدم باعتباره رقم عيادة، ولا يُنقل بين شبكات مختلفة دون علاقة مسجلة. العناوين المتعددة لها روابط منفصلة؛ عند عدم وجود رابط معتمد يُعرض «البحث عن العنوان» في خرائط Google، دون اختلاق موقع مؤكد.
5. اقرأ التقييم الإجمالي وعناصره وملاحظات الأعضاء المسموح بنشرها دون أسماء. لا ترسل المعاينة تقييمًا جديدًا؛ حساب المدير لا ينتحل عضوًا، ولا تُنشر الملاحظات الخاصة.
6. ارجع للنتائج؛ يعاد البحث والتصفية والتمرير. التقدم في المتصفح يعيد المقر والتبويب المختارين. ينتهي هذا السياق بإعادة تحميل الصفحة أو الخروج؛ لا يحفظ البحث الخام أو الدليل في تخزين المتصفح.

تُعرض آخر نشرة خبر منشورة إذا كانت سارية دون الحاجة لفتحها، ولا تُحوّل تحديثات الدليل إلى أخبار تلقائيًا. الدليل لقطة وقت التحميل؛ زر «تحديث الدليل» يجلب التعديلات اللاحقة، ولا يُدّعى تحديث لحظي للمحتوى.

## الفصل والتحقق

- `GET /v1/admin/lab/preview/directory_experience` يتطلب جلسة مدير يتحقق الخادم منها حيًا، ثم يتحقق من إيقاف المعاينة. يعيد إسقاط الدليل نفسه المسموح للعضو، مع إحصاءات التقييم المنشور فقط. الجهات المخفية والمسودات وأبناء جهة مخفية مستبعدة.
- `?status=1` يعيد بيانات حالة المعاينة فقط دون إعادة تنزيل الدليل. تستخدمه الواجهة كل 20 ثانية أثناء ظهور الصفحة وعند العودة إليها؛ لا يجدد جلسة المدير ولا يمنع خمول العشر دقائق.
- فشل التحقق أو الإيقاف يزيل بيانات المعاينة وDOM الخاص بها. يخفي التبويب العائد المحتوى حتى نجاح التحقق، وفقد الاتصال يوقف العرض. قد يبقى المحتوى حتى الفحص الدوري التالي إذا تغيرت الصلاحية أو الإيقاف من جلسة أخرى؛ لا وعد بمحو صور أو محتوى سبق الاطلاع عليه.
- كل انتقال يلغي مؤقتات ومراجع العرض السابق، ويتجاهل الردود المتأخرة. البيانات في ذاكرة الصفحة فقط؛ لا ملفات أعضاء أو بيانات تحقق أو بحث خام في Git أو التخزين المحلي.
- مسارات `#lab-directory` و`#lab-directory=<id>` و`#lab-specialties` لا تمنح صلاحية. العضو والزائر مرفوضان خادميًا حتى باستدعاء API مباشرة أو تزوير الدور محليًا.
- لا كتابة إلى الدليل أو التقييمات أو الأخبار أو الإشعارات أو MyNekaba. تحفظ مراجعة هذه المعاينة فقط في مساحة المعمل القائمة، بإصدار مستقل وفحص التعارض. تغيير البنية أو الرحلة لاحقًا يتطلب رفع مراجعتها وتجديد الحكم؛ لا يستبدل اعتمادًا قديمًا تلقائيًا.

## التشغيل وفصل النشرين

تحتاج الواجهة 4.14.0 وخدمة تعلن `development-directory-v1`. الخدمة الأقدم تبقي النماذج الثلاثة متاحة، وتعرض تنبيهًا بأن التجربة الجديدة تحتاج تحديث Firebase. البيئة الحالية لا تملك هوية Google لنشر الخدمة؛ اكتمال الواجهة أو اختبارات CI ليس دليل تفعيلها.

من Cloud Shell المخول:

```bash
cd ~/cloudshell_open/Medical &&
git pull --ff-only origin main &&
bash scripts/deploy-medical.sh --existing-config
```

يتحقق المساعد بعد النشر من القدرة الجديدة ويحافظ على الإعداد الحالي، مستهدفًا Medical فقط. لا يغير مشروع MyNekaba أو صلاحياته. يمكن التحقق العام بعدها دون حساب أو قراءة بيانات:

```bash
node scripts/check-live.mjs --rayati --require-development-lab --require-directory-preview
```

نجاح `development-lab-v1` وحدها لا يثبت إتاحة التجربة الجديدة. نشر هذه القدرة مرة واحدة لا يعني نشر كود بعد كل تعديل سجل في لوحة الإدارة.

## أدلة القبول والرجوع

نجحت 139 حالة اختبار للوحدات والحماية، مع اختبارات معاملات Firestore المحلية الفعلية واختبار المتصفح الشامل. تشمل الأدلة: البحث عن مركز من الرئيسية، فصل هواتف وشبكات الفرع، تصنيف المركز بعد تعديله، بقاء هوية التقييم الصحيحة، خصوصية الملاحظات، استعادة البحث والتمرير والمقر عبر الرجوع والتقدم، والتخصصات وإيقاف المعاينة وسحب صلاحية المدير. عرض 320 و390 و768 و1440 بكسل دون تجاوز أفقي أو أخطاء JavaScript. بيانات الاختبار مصطنعة ولا تُنشر لقطات مراجعات حقيقية.

هذه الأدلة لا تعادل اختبار جميع بيانات الإنتاج أو موافقة تعميم. ما زالت معاينة قراءة خاصة ضمن P1؛ خدمات «جهّز زيارتي» والبلاغات في P2 لم تنفذ بهذا الإصدار، وخيارات تكبير الخط من N-D06 كذلك.

للرجوع: أوقف «تجربة الدليل المترابطة» وحدها من «الملاحظات والقرار» في المعمل؛ تبقى النماذج الأخرى وواجهة الأعضاء. يمكن استعادة إصدار واجهة وخدمة متوافقين دون حذف سجلات المعمل أو ترحيل بيانات الدليل. لا تغيير لقواعد Firestore الحالية.
