# ربط نبض النقابة على Vercel بخدمة Medical

الرابط الذي أكده المالك: https://medical-nekaba.vercel.app/

## التشخيص — 18 أكتوبر 2026

- صفحة Vercel و`/js/config.js` أعادا الحالة 200، والإعداد يشير إلى خدمة Medical الصحيحة.
- طلب OPTIONS إلى `/v1/member/session` مع Origin الخاص بـVercel أعاد 403 و`ORIGIN_DENIED` دون Access-Control-Allow-Origin.
- طلب GitHub Pages المناظر أعاد 204 وأعاد فحص الصحة 200. لذلك يعرض المتصفح خطأ اتصال قبل إرسال بيانات تسجيل الدخول.
- لا يتعلق التشخيص بكلمة المرور أو أهلية العضو؛ لم تُرسل بيانات دخول حقيقية ولم تُختبر مدخلات الصورة.

## الإصلاح

`functions/src/origins.mjs` يسجل نطاقي الإنتاج المعروفين صراحة، ويجمعهما مع إضافات البيئة الصحيحة. يرفض HTTP والمستخدم/كلمة المرور والمسارات والمنافذ غير القياسية وwildcards. النطاقات المشابهة والمعاينات الأخرى غير مسموحة.

مساعد `scripts/deploy-medical.sh` يحتفظ بنطاقات البيئة السابقة عند تجديد الإعداد، ثم يفحص OPTIONS بعد النشر. يفحص مسار GitHub للنشر الخلفي رابط Vercel كذلك. لا تتغير شروط الجلسة أو الدور أو العضوية، ولا يُفتح الدليل دون تسجيل دخول.

اختبارات الوحدة تغطي ملف البيئة القديم، وإعادة تجهيز الإعداد دون نشر، والاحتفاظ بالنطاق المخصص، ورفض إعداد غير آمن قبل الكتابة، والسماح الدقيق للنطاقين، ورفض المعاينة، و401 للدليل دون جلسة. بيانات الاختبار مصطنعة ولا تحتاج Google.

## التفعيل من Cloud Shell

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only && bash scripts/deploy-medical.sh --existing-config
```

ثم:

```bash
node scripts/check-live.mjs --vercel
```

نجاح الفحص يعني وصول الصحة وOPTIONS من الرابطين وبقاء الدليل محميًا، ولا يعادل تجربة دخول حقيقية. بعده يعيد المالك فتح Vercel وتجربة العضو والمدير. الجلسة المحفوظة على GitHub لا تنتقل تلقائيًا إلى أصل Vercel؛ قد يلزم الدخول مرة أخرى، دون تغيير الحساب.

لا حاجة إلى أسرار جديدة أو تغيير قواعد Firebase أو بيانات MyNekaba. تظل خدمة Medical في مشروعها المستقل. هذه الجلسة لا تملك هوية Google للنشر؛ الحالة حتى نشر الوظيفة: إصلاح جاهز، وتفعيل الإنتاج ينتظر إجراء Cloud Shell أعلاه. لا تطلب بيانات تحقق العضو لإصلاح CORS.
