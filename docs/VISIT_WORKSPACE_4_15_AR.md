# الزيارة والبلاغات التجريبية — رعايتي 4.15.0

21 أكتوبر 2026 — بدء معاينة خاصة ضمن P2، وفق [الاتفاقية](../APP_AGREEMENT_AR.md) و[الخارطة](PHASED_PREVIEW_ROADMAP_AR.md). توجيه المالك: استمرار تحديثات الإدارة دون نشر وظائف جديدة للأعضاء.

## مكان المراجعة

**الإدارة ← معمل التطوير ← جهّز زيارتي والبلاغات ← فتح المعاينة**. ابحث عن جهة، وافتح تفاصيلها ثم تبويب **جهّز زيارتي**. من الشريط العلوي أو من ملخص الزيارة افتح **مركز البلاغات التجريبية**.

هذه خامس معاينة مستقلة: `visit_workspace` ومراجعتها `p2-visit-20261021-1`. لها قرارها وإيقافها الخاصان، ولا ترث اعتماد النماذج الأربعة السابقة أو تبدل مراجعتها. جمهورها «إدارة» خادميًا؛ لا يوجد زر تفعيل للأعضاء. مسارات `#lab-visit` و`#lab-visit=<id>` و`#lab-visit-specialties` ليست تصريح وصول.

## تجربة الزيارة

- البيانات من إسقاط الدليل المنشور نفسه الذي يسمح به للأعضاء؛ تستبعد الجهات المخفية والمسودات والجهات التابعة لمستشفى مخفي. اختيار المقر وشبكة العرض يحدد العنوان والمواعيد والهواتف والحالة. يظل المحمول والأرضي والمختصر منفصلة، وتوضح هواتف استقبال المستشفى البديلة.
- الروابط المسجلة أو بحث خرائط Google بالعنوان؛ لا إحداثيات مصطنعة ولا وعد بموقع موثق أو زمن وصول. تعدد العناوين يعرض كل عنوان منفصلًا.
- التعليمات المعروضة منشورة وسارية ومناسبة لشبكة العرض إن كان لها نطاق مسجل. تسمى «تعليمات منشورة بالدليل» عامة؛ لا تُنسب لجهة بعينها أو تُختلق شروط تغطية أو موافقات أو مستندات أو تحضيرات طبية.
- اختيارات «راجعت العنوان/المواعيد/اتصلت بالجهة» في ذاكرة المعاينة فقط، مستقلة لكل جهة ومقر وشبكة عرض. تعود عند تبديل التبويب والرجوع والتقدم، وتنتهي بإعادة تحميل الصفحة أو الخروج. ليست إثبات اتصال أو حصول خدمة، ولا تحفظ بيانات عضو.
- «قراءة أوضح» يكبر محتوى المعاينة فقط، دون إعداد يؤثر في واجهة العضو أو حفظ تفضيل شخصي.

## مسار البلاغ التجريبي

الإنشاء باختيار مثال جاهز: رقم، عنوان، مواعيد، تعاقد، أو اسم/تخصص. يختار المدير شبكة المستفيد من شبكات المقر المسجلة. لا نص حر ولا هاتف شخصي ولا اسم عضو ولا تشخيص ولا ملف مرفق؛ هذه مساحة لاختبار المسار وليست استقبال بلاغات حقيقية.

المراحل: **تجربة جديدة ← قيد الفحص التجريبي ← اكتملت التجربة**، أو الاستبعاد من الحالتين المفتوحتين. الإكمال يختار نتيجة ثابتة: اكتمال اختبار الفحص، أو مثال يحتاج الرجوع للمصدر، أو عدم تكرر المشكلة في المثال. النتيجة لا تصحح الجهة ولا تعتمد التعاقد؛ لا يوجد ادعاء بعمل لم يحدث.

لكل مثال رمز `LAB-…` وإصدار وسجل توقيت القاهرة. يمكن تصفية المركز بالحالة؛ العدادات من الأمثلة المحفوظة فعلًا. المثال المطابق المفتوح لنفس الجهة والمقر والشبكة والنوع يعاد دون تكرار حتى لو وصل معرف طلب جديد. إعادة الطلب نفسه مطابقة لا تكرر الكتابة؛ إعادة معرفه ببيانات مختلفة تُرفض. لا يجوز تجاوز مرحلة الفحص، أو تغيير حالة نهائية، أو الكتابة بقرار قديم فوق إصدار أحدث.

## التخزين والصلاحيات

- `GET/POST /v1/admin/lab/visit-reports` و`PATCH /v1/admin/lab/visit-reports/<id>` تتحقق خادميًا من حساب المدير الحي، ثم مراجعة المعاينة وإيقافها. الزائر والعضو مرفوضان ولو بالاستدعاء المباشر أو تزوير دور المتصفح. كل الاستجابات `no-store`.
- تتحقق الخدمة عند الإنشاء من الجهة والمقر والشبكة في الدليل المنشور. لا تحول تغيير الفئة إلى هدف تقييم أو بلاغ مختلف؛ يبقى معرف المصدر ثابتًا.
- مثال البلاغ في `medical_lab_scenarios/visit_workspace` منفصل عن الدليل والأخبار والتقييمات والطلبات والإشعارات. معاملة Firestore تقرأ حالة المعاينة وبيانات الأمثلة قبل الكتابة؛ الإيقاف المتزامن يمنع الكتابة. سجل التدقيق الخاص يحتوي الفاعل والمعرف والإصدار والتوقيت، دون محتوى عضو.
- الحد 100 مثال: لا تُحذف تجربة مفتوحة لإضافة أخرى. عند بلوغ الحد يمكن أن تخرج أقدم تجربة مكتملة أو مستبعدة؛ إذا كانت كلها مفتوحة يرفض الإنشاء حتى إكمال بعضها. تاريخ المثال محصور بآخر 8 انتقالات؛ المسار الحالي يصل إلى 3. هذه حدود اختبار وليست سياسة بيانات أعضاء.
- تستمر إعادة التحقق الخفيفة كل 20 ثانية وعند العودة للتبويب؛ لا يعاد تنزيل الدليل دوريًا ولا تُمدد الجلسة. الإيقاف أو فقد الصلاحية أو الاتصال يزيل المحتوى، والردود المتأخرة لا تعيد ملء شاشة مغلقة. قد يبقى المحتوى حتى الفحص التالي عند تغير الحالة من جلسة أخرى.
- قواعد Firestore تمنع وصول المتصفح المباشر للمجموعات كافة. لا تغيير لـIAM أو Auth أو كود أو بيانات MyNekaba، ولا استخدام لهوية القراءة للكتابة.

## التشغيل والرجوع

تحتاج الخلفية `development-visit-v1` والواجهة 4.15.0. الخدمة الأقدم تعرض تنبيهًا لتحديث Firebase؛ لا تظهر بيانات محلية بديلة ولا تمنح العضو المعاينة. قدرة P1 وP2 لا تُعدان منشورتين لمجرد وجود ملفات الواجهة أو نجاح اختبارات CI.

من جلسة Cloud Shell المخولة، عند تشغيل معاينة الإدارة:

```bash
cd ~/cloudshell_open/Medical &&
git pull --ff-only origin main &&
bash scripts/deploy-medical.sh --existing-config
```

المساعد يستهدف Medical فقط ويحافظ على الإعداد الموجود. فحص عام دون حساب حقيقي:

```bash
node scripts/check-live.mjs --rayati --require-development-lab --require-directory-preview --require-visit-preview
```

للرجوع: أوقف خامس بند وحده من «الملاحظات والقرار»؛ تبقى النماذج الأخرى والأعضاء كما هم. لا يلزم حذف الأمثلة لإيقاف العرض. استعادة واجهة وخدمة متوافقتين ممكنة دون ترحيل بيانات التشغيل. لا تعميم للأعضاء في هذه المرحلة؛ يلزم تنفيذ وربط وقبول مستقل لأي استقبال بلاغات فعلية لاحقًا.
