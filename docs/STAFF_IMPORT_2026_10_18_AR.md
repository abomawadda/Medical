## البطاقات والصور وتجربة الدخول

يحافظ الدليل على هوية الطبيب الواحدة ومقاره وعلاقاته الحالية. يضيف المصدر علاقة موظفين مباشرة وفق القائمة؛ نطاق السلاب والخير المشترك والحكمة للموظفين موثق من شرح المالك، دون تأكيد كل خدمة أو نسبة تحمل تلقائيًا. المواعيد غير الموجودة تظهر «تحتاج تأكيدًا»، والتغطية المالية تظل غير مؤكدة.

أضيفت ثلاثة شعارات تعريفية من مواقع الجهات نفسها: تكنوسكان والبرج والعزبي، وتظهر في 15 سجلًا من الاستيراد مع رابط المصدر. نُقلت ملفات العلامات كما هي دون تعديل، ولا تقدم على أنها صور الأطباء أو صور الفروع. تفاصيل المصدر والمسار الأصلي في `img/providers/SOURCES.md`. بقية الجهات تعرض «صورة غير مضافة» إلى أن تتوفر صورة صحيحة. نموذج المدير يسمح بإضافة رابط صورة HTTPS ومصدرها وتأكيد هوية صاحبها وحق الاستخدام؛ يمنع حفظ الصورة إلى خلفية قديمة لا تدعمها بدل إظهار نجاح وهمي.

الدخول والتحميل يعرضان شعار النقابة وWE بنسبة صحيحة فوق خلفية بنفسجية متدرجة؛ تُخفى مستطيلات الخلفية البيضاء بالمزج في CSS دون تغيير العلامات الأصلية. يظهر «إعداد وتنفيذ أ / محمود العراقي» و01550100025 كرابط اتصال. اختار المالك اسم «نبض النقابة»، ووُحد في التحميل والدخول والعنوان واسم التثبيت، مع وصف «رفيقك للرعاية والخدمات النقابية — WE».

فلاتر المركز تشمل مراكز الدقهلية الستة عشر، بما فيها المناطق بلا نتائج. فلاتر الشبكة ومسار التعاقد مستقلة عن إثبات التغطية. جُمعت الفلاتر في مساحة قابلة للفتح لتبقى البطاقة قريبة من المستخدم على الموبايل. بيانات المحافظة تستخدم `country_code` و`governorate_code` ومدينة/مركز مستقلين؛ التشغيل الحالي محلي، وإضافة محافظة جديدة لاحقًا تحتاج بيانات وتفعيل نطاق معلومين، وليست ظهور جهات خارج الدقهلية بالخطأ.

## إعادة الإنتاج والملفات

```sh
# يحتاج openpyxl محليًا لمعالجة Excel فقط؛ لا تعتمد الوظيفة أو الواجهة عليه.
python scripts/import_staff.py --source /private/path/testaff.xlsx --output-dir /private/output
python build_dataset.py
python scripts/export-directory.py --output /private/output/merged-directory-organized.xlsx
node scripts/prepare-seed.mjs
npm test
npm run build
npm run check
npm run test:browser
```

`staff-network-organized.xlsx` يحتوي ملخصًا وجهات جاهزة ومعلقة وخارج النطاق وأرقامًا مصنفة وعلاقات تعاقد وملاحظات وسجل تصحيحات. الأرقام محفوظة كنص للحفاظ على الصفر الأول. `merged-directory-organized.xlsx` يجمع بيانات الجهات السابقة والجديدة من المستودع فقط. نسخة الأصل في `staff-source-preserved-private.xlsx` محلية منفصلة، ولا تدخل Git أو حزمة الموقع.

المصدر المنظم في `imports/staff-20261018.json` إسقاط لبيانات مقدمي الخدمة المقبولة فقط، مستبعد من موقع Pages وحزمة dist. مثل `data.json` يظل مصدر المستودع العام قابلًا للقراءة عبر GitHub؛ تسجيل الدخول يحمي API ولا يحول المستودع العام إلى مخزن سري. لا يوضع فيه ملف موظفين أو تعليقات مراجعات أو ملف المصدر الإداري الكامل.

الإضافة قابلة لإعادة البناء دون تغيير المعرّفات أو مضاعفة السجلات، ولا تحذف سجلات دليل قديمة لم يذكرها الملف. تعديلات الإدارة المركزية وتجميدات الحذف لها أولوية على seed؛ لم تُقرأ هذه التعديلات الإنتاجية في جلسة المساعد، ولا يكتب الاستيراد إليها فوقها تلقائيًا. تظل المطابقات المحتملة غير المؤكدة خارج أي دمج آلي.

## النشر والقبول

الواجهة تُنشر عبر GitHub Pages. وصول السجلات الـ79 وإمكانات الصور إلى الخدمة المركزية يحتاج نشر وظيفة Firebase بالـseed المحدث؛ تغيير الواجهة وحدها لا ينفذ ذلك. يعلن health دعمي `staff-directory` و`provider-images`، ويختبر مسار النشر وجودهما، ثم يجرب المالك الدخول وفتح تكنوسكان والحكمة وعيادة الأسنان الجديدة. الأتمتة الخلفية لا تزال غير مربوطة بهوية Google؛ لا يُعتبر تجاوز deploy في Actions نجاح نشر.

الأمر من Cloud Shell الخاص بالمالك، إذا بقي إعداد المشروع المحفوظ:
