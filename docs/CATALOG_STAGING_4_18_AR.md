# مركز جودة الدليل ودفعات المراجعة — 4.18.0

## ما تم تجهيزه ومن يراه

من لوحة الإدارة ← معمل التطوير ← **جودة الدليل ودفعات الاستيراد**. هذه المعاينة الثامنة مستقلة بمراجعة `catalog-staging-20261021-1` للبنود C06/C07/O05، ولا ترث اعتمادًا سابقًا. تحقّق كل قراءة وقرار من حساب المدير الحي في المصدر؛ تخزين الدور في المتصفح أو كتابة رابط المعاينة لا يمنح صلاحية. التعطيل متاح من بطاقة المعمل ويعاد فحصه داخل معاملة الحفظ.

الواجهة الحالية للأعضاء مستمرة. لا يكتب هذا المسار إلى الجهات أو التعاقدات أو التقييمات أو الأخبار أو العضويات، ولا يرسل إشعارًا. «قبول للمراجعة» يخص الصف داخل دفعة حساب المدير فقط. **الاستيراد إلى دليل الإنتاج وزر نشر الدفعة والتراجع عن دليل منشور لم تُفعّل**؛ تبقى مرحلة مستقلة بعد مراجعة هذه التجربة. يظل C07 جزئيًا وفق هذا الحد.

## رحلة استخدام عملية

1. افتح «دفعة جديدة»، واختر XLSX أو CSV UTF-8 أو TSV، أو الصق جدول Excel متضمنًا عناوين الأعمدة. يمكن تنزيل قالب فارغ. XLS/XLSM والملفات المشفرة غير مدعومة؛ تحفظ نسخة XLSX عادية.
2. اختر الورقة؛ تعطى «الدليل المنقح» أولوية إن وجدت. اختر صف العناوين الفعلي عند وجود مقدمة، ثم راجع اقتراحات ربط الأعمدة. الأعمدة غير المرتبطة لا تُرسل إلى الخادم.
3. اختر قسمًا واحدًا للدفعة: أطباء، مستشفيات، تحاليل، أشعة، صيدليات أو مراكز متخصصة، واكتب مرجعًا واضحًا للملف. لا يستنتج التطبيق أهلية المستفيد أو جهة التعاقد أو سريانه من الاسم.
4. الاسم مطلوب، والعنوان والمركز مطلوبان للسجل الجديد. المعرّف الحالي اختياري للجديد، وإلزامي لاقتراح تعديل سجل موجود. لا تُنشأ معرّفات إنتاج من الملف، ولا تستبدل خلية فارغة قيمة قائمة. لاقتراح مسح قيمة لاحقًا يلزم إجراء مستقل صريح.
5. راجع مجموعات حتى 30 صفًا، ثم «فحص وحفظ الدفعة الخاصة». يقرأ الخادم لقطة الدليل الحالية بما فيها الجهات المخفية والموقوفة؛ لا يقرأ ملفات أعضاء أو نصوص مراجعات لهذا الغرض، ولا يعيد مستندات الجهات الكاملة للمتصفح.
6. صفِّ حسب نتيجة الفحص. افتح الفروق لرؤية القيمة الحالية والمقترحة، والأسماء المشابهة. أرقام المحمول والأرضي والمختصر تظهر في أقسام مستقلة. فحص الصيغة لا يثبت أن الرقم يرد أو أن العنوان صحيح ميدانيًا.
7. حدد عدة صفوف واقبلها للمراجعة أو استبعدها. الصفوف الناقصة والملتبسة والمكررة أو المطابقة لا تقبل كتعديلات؛ عملية مختلطة فيها صف محظور ترفض كاملة دون قبول بقية الصفوف جزئيًا.
8. «تراجع عن آخر قرار» يعيد قرارات الصفوف السابقة داخل الدفعة. «استبعاد الدفعة» يمنع أي قرار جديد عليها؛ بعدها يمكن حذف نسختها الخاصة لتفريغ المساحة. لا يستدعي ذلك استعادة بيانات تشغيل، لأنها لم تتغير أصلًا.

## قواعد المطابقة والتصحيح

- يعتمد تعديل السجل على معرّفه داخل القسم المختار، وليس اسمه وحده. المعرّف المفقود أو المتكرر لا يوجه تعديلًا إلى سجل مفترض.
- الاسم المماثل مع العنوان نفسه **تكرار محتمل** يحتاج تحقيقًا، وليس أمر دمج. الاسم نفسه في عنوان مختلف ينبه إلى فرع محتمل دون حذفه. مشاركة رقم استقبال وحدها لا تعتبر تكرارًا. لا تتحول التعاقدات المتعددة إلى تعاقد واحد تلقائيًا.
- تُحفظ القيم الأصلية المرسلة وتعرض التصحيحات العربية المحافظة كفروق؛ لا تخمين للألقاب والقرى والأسماء غير المعروفة. المعرّف لا يخضع لتصحيح لغوي.
- لا تقبل حقول تغيير الإخفاء والإيقاف والأهلية والشبكات وموافقة النشر في طلب الاستيراد. تظهر حالات الإخفاء والإيقاف الحالية كتنبيه، وتبقى دون تغيير.
- عند القبول الخاص، يعاد فحص الصفوف مقابل قراءة جديدة للدليل ومقارنة لقطة السجل والتطابقات؛ التغيير المكتشف يرفض القرار ويطلب دفعة جديدة. هذه مقارنة وقت المراجعة، وليست قفلًا مستمرًا لسجل الإنتاج. القرارات المحفوظة تصف لقطة الفحص ولا تثبت بقاء المصدر مطابقًا إلى الأبد.

## حدود الملفات والخصوصية

قراءة XLSX وفك الضغط وتحليل XML محلية في المتصفح؛ لا يُرفع المصنف أو يرسل إلى خدمة خارجية. تُرفض المعادلات في الأعمدة المرتبطة ولا تنفذ حتى إن احتوت قيمة مخبأة. تُرفض تعريفات XML الخارجية ومسارات الأرشيف غير الآمنة والملفات المضغوطة التالفة أو غير المدعومة؛ تفحص أحجام الفك الفعلية وCRC. لا ينفذ VBA أو اتصال روابط خارجية.

حد الملف 5 ميجابايت؛ CSV/TSV ميجابايت نص واحد؛ الأرشيف 200 عنصر وإجمالي فك معلن 20 ميجابايت، و8 ميجابايت للجزء المقروء؛ 1000 صف بيانات و40 عمودًا، و2000 حرف للخلية عند القراءة، و500 حرف للقيمة المرسلة. قد يلزم فصل ملف الدليل في ورقة مختصرة إذا احتوى أعمدة أو صفوفًا كثيرة من تنسيقات Excel. أرقام الهاتف تحفظ **كنص**؛ لا يخمّن النظام صفرًا فقده Excel من رقم حُفظ كعدد.

ترفض عناوين بيانات الأعضاء المعروفة، والقيم المشابهة لرقم قومي من 14 رقمًا يبدأ بـ2 أو3، والمفاتيح غير المسموحة. لا يمكن لهذا الفحص اكتشاف كل معلومة شخصية قد تكتب داخل نص حر؛ المسؤولية أن يختار المدير **ملف الجهات فقط**، دون بيانات أعضاء أو بيانات صحية أو أسرار. لا يُحفظ الملف في localStorage ولا يضاف للمستودع. تحفظ الحقول المحددة فقط في مساحة حساب المدير داخل Medical.

حد الدفعة 30 صفًا وطلب HTTP 32768 بايت. حد مساحة المدير خمس دفعات و700000 بايت للحالة؛ لا تحذف دفعة تلقائيًا. يحتفظ كل سجل دفعة بـ30 قرارًا للتراجع دون إزاحة صامتة للقديم. آخر 40 معرف عملية يحمي إعادة الطلب؛ تعارض النسخة يمنع كتابة قرار قديم. فقد الرد يحتفظ بالعملية نفسها لإعادة المحاولة بدل إنشاء قرار مكرر. سجل التدقيق يحمل نوع العملية والنسخة والهوية والوقت فقط، دون أسماء الجهات أو محتوى الملف.

## التشغيل والرجوع

قدرة الخلفية المطلوبة `development-catalog-staging-v1` والواجهة 4.18.0. لوحة الجاهزية تغيرت إلى `p0-readiness-20261021-2` لتضيف أعداد الدفعات الخاصة والصفوف المقبولة للمراجعة في P1؛ التقارير أعداد ولا تصدر أسماء أو محتويات دفعات.

نشر الواجهة عبر Vercel/Pages لا ينشر Firebase. من Cloud Shell الخاص بالمالك:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only origin main && bash scripts/deploy-medical.sh --existing-config
```

إن ظهرت مشكلة المصادقة، ينفذ في الجلسة نفسها أولًا:

```bash
npx --yes firebase-tools@15.34.0 login --reauth --no-localhost
```

ثم يعاد أمر النشر. لا تشارك رمز الدخول. للفحص العام دون الدخول أو قراءة أي سجل خاص:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --require-catalog-staging --require-service-workflow --require-roadmap-preview --require-development-lab --rayati --vercel
```

للرجوع أوقف بطاقة الجودة من المعمل. الدفعات محفوظة ولا تتغير بيانات الأعضاء. عند العودة لإصدار قديم لا يعتمد على عرض الدفعات غير المتوافقة؛ تظل المعاينة موقوفة إلى عودة نسخ متوافقة. لا يوجد ترحيل إنتاج في هذه الحزمة.

## الفحوص

اختبارات مصطنعة للقراءة والمطابقة والفروع والتكرار والأرقام والإملاء ورفض البيانات الحساسة، وحظر العضو والزائر وإلغاء صلاحية المدير، والتعارض والتراجع وتغيير المصدر وإعادة الطلب وإيقاف المعاينة داخل المعاملة. اختبار متصفح يقرأ XLSX مضغوطًا فعليًا، ويرفض المعادلات وXML الخارجي، ويجرب فقد رد الحفظ والتراجع، ومقاسات 320–1440. اختبار Firestore Emulator يؤكد المعاملات وعزل حساب المدير وثبات دليل الأعضاء وبيانات المصدر. لا يُستخدم دخول عضو حقيقي أو ملف أعضاء لإثبات الاختبار.

نتيجة التحقق المحلي في 21 أكتوبر 2026: **172 اختبار وحدة وحماية ناجحًا**، وفحص الأصول والبناء ناجح، ورحلة المتصفح الكاملة ناجحة دون أخطاء تشغيل، واختبار Firestore Emulator ناجح. الاختبارات تشمل ثبات مصدر العضوية ودليل الأعضاء. فحص الإنتاج في بداية العمل أثبت نشر قدرة 4.17 السابقة؛ قدرة الاستيراد الجديدة لم تكن موجودة. لم تتوفر هوية Google للنشر من جلسة التنفيذ، لذلك يبقى نشر Firebase لهذه الحزمة خطوة تشغيل من Cloud Shell الخاص بالمالك. لا يُعد نجاح نشر الواجهة أو مهمة جاهزية GitHub بديلًا عن هذه الخطوة.
