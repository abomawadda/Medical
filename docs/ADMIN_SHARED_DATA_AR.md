# تعديل البيانات المشتركة للمحدد — 4.4.0

وسّع المالك اختياره السابق إلى «الحالات والبيانات المشتركة معًا». تبقى الحالات الأربع، ويضاف اختيار «تعديل البيانات المشتركة» إلى معاينة التحديد. هذا القرار الأحدث يتقدم على حصر 4.3.0 في الحالات.

## الحقول والنطاق

- المركز: يحدّث markaz وcity معًا. يحفظ نص العنوان، ويمسح رابط الخريطة إذا تغير المركز حتى يراجع المدير العنوان والموقع؛ لا ينشئ إحداثيات بديلة. قد يحتاج ربط السجلات المتطابقة إلى مراجعة عند تغيير مركزها، وفق حارس هوية الفرع القائم.
- التخصص: عند تحديد أطباء فقط. يلزم تحديد جميع مقار الطبيب التي ستختلف تخصصاتها عن القيمة الجديدة، فلا ينشأ اختلاف خفي بين مقار بطاقة الطبيب نفسها.
- التصنيف: عندما تكون السجلات من نوع جهة واحد، مثل عدة مستشفيات أو عدة معامل. لا يطبق تصنيف مستشفى على صيدلية بسبب تحديد مختلط.
- المستفيدون: الموظفون أو الأسر والمعاشات أو الجميع. اختيار الفئات يستبدل القائمة الحالية للمحدد، ولا يغيّر نسب التحمل أو أسماء التعاقدات أو مستنداتها أو حالة الاعتماد.

لكل حقل «دون تغيير» افتراضيًا. الأسماء والعناوين وأرقام الاتصال والمواعيد والروابط التنظيمية وشروط التعاقد ليست حقول تعديل جماعي. التعليمات والطوارئ خارج تعديل البيانات المشتركة؛ تبقى عمليات الحالة المستقلة كما كانت.

## المعاينة والأمان

يعرض زر «معاينة التغييرات» الاسم والمعرف والقيمة الحالية والجديدة لكل سجل ولكل حقل مختار. يلزم إقرار مراجعة القيم قبل التطبيق. تغيير اختيار حقل أو العملية يبطل المعاينة والإقرار، فلا يكفي تأكيد معاينة قديمة. يقبل الخادم الحقول الأربعة وحدها ويمنع الحقول الإضافية، سواء أرسلت من الواجهة أو من طلب مباشر.

يحفظ حتى 50 سجلًا في معاملة واحدة، مع صلاحية المدير وأرقام النسخ الحالية لكل سجل. التكرار داخل التحديد، ونوع سجل غير متوافق، وتعارض النسخة، وقيم شبكة غير معروفة ترفض العملية كاملة. لا يكتب شيئًا إلى مصدر MyNekaba، ولا ينشئ خبرًا للأعضاء أو يعتمد جهة تعاقد تلقائيًا. يسجل التدقيق `entity.batch.data` في Medical فقط.

## الشبكات المستوردة

كانت عملية إلحاق حقائق الأسر التاريخية تضيف شبكة الأسر إلى تجاوزات قديمة. بعد اختيار المدير الصريح لفئات جديدة، يحفظ الخادم علامة `network_override` ويستعمل القائمة التي اختارها، مع حفظ علاقات المصدر وأدلتها التاريخية. لا يستطيع طلب تعديل عادي تزوير هذه العلامة أو مسحها؛ تحفظ مع تحرير السجل اللاحق. لا يعني تعديل التصنيف اعتماد تغطية مالية جديدة.

## التفعيل

الواجهة 4.4.0، وتحتاج عملية الحفظ الجديدة قدرة `admin-batch-data-v1` في Firebase. يستمر تغيير الحالات على قدرته السابقة. إلى نشر الخدمة، تعرض محاولة حفظ البيانات المشتركة تنبيهًا للإدارة ولا ترسلها إلى مسار يتجاهلها.

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only && bash scripts/deploy-medical.sh --existing-config
```

NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --vercel --require-admin-batch-data

## التحقق

نجحت 91 وحدة اختبار، ورحلة المتصفح الكاملة بما فيها معاينة وتطبيق المركز والمستفيدين على مستشفيين مع الحفاظ على الهواتف، واختبار Firestore للحفظ الذري وتعارض النسخ. تشمل الوحدة منع تعديل الاسم أو النشر ضمن طلب البيانات، وصون اعتماد التعاقد، وعدم إعادة شبكات أزيلت صراحة، ومنع اختلاف تخصص مقار الطبيب بسبب تحديد ناقص. فُحص بناء الأصول وحدود النشر؛ لا يعد هذا تحققًا من بيانات أعضاء الإنتاج أو إثباتًا لنشر Firebase.
