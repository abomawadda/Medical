# مكتب متابعة المدير — 4.20.0

## ما يضيفه ومن يراه

استكمال D08/C06 وجزء من مؤشرات M01، داخل «الإدارة ← معمل التطوير ← مكتب متابعة المدير». عينة تاسعة مستقلة `admin_inbox` بمراجعة `admin-inbox-20261023-1`، وتحقق حي من المدير وإيقاف من المعمل. لا تُورث موافقات النماذج السابقة، ولا تفعّل الموافقة على التصميم هذه الأدوات للأعضاء.

الشاشة تجمع **أعدادًا من التشغيل الحالي** وملاحظات آلية على الدليل والمحتوى، مع **سجل متابعة خاص بكل مدير**. لا تعني الأعداد قياس استخدام الأعضاء أو رضاهم أو زمن الخدمة، ولا تسجل زيارة أو علاجًا. لا تغير الشاشة ملفات الجهات أو التعاقدات أو التقييمات أو طلبات تعديل الأعضاء أو MyNekaba، ولا ترسل إشعارات.

## قوائم الانتظار دون بيانات أصحابها

ثلاث بطاقات: سجلات تقييم بحالة `pending`، وطلبات تعديل بيانات بحالة `pending`، وطلبات بحالة `applying` تحتاج متابعة التحقق. تقرأ الخدمة أعدادها باستعلامات Firestore التجميعية داخل Medical؛ لا تحمل نصوص التعليقات أو تغييرات ملفات الأعضاء أو أسماءهم لهذه الأعداد.

الأعداد تمثل **سجلات الحالة**، وليست عدد أشخاص فريدين. قد تتطلب التقييمات القديمة مراجعة النسخ المرتبطة عند فتح الأداة الأصلية. أداة تعديل البيانات القائمة تعرض لقطة محدودة؛ لا تعني بطاقة العدد أن أدوات المراجعة التاريخية أصبحت نظام ترقيم صفحات كاملًا بهذا الإصدار.

عند فشل قراءة مصدر يظهر «غير متاح»، دون تحويله إلى صفر أو إخفاء عمل معلق. قد تبقى بقية الأعداد وملاحظات الدليل متاحة. فتح قوائم المراجعة يستخدم أدوات الإدارة القائمة ويتطلب صلاحيتها؛ لا يعتمد أو يعدل شيئًا تلقائيًا. قراراتها الفعلية تبقى خاضعة لضوابطها السابقة.

## ملاحظات الدليل والمحتوى

- أرقام غير سليمة الصيغة أو مفقودة، ومعرّفات غير مكتملة أو مكررة، وأسماء وعناوين ومراكز وتخصصات ناقصة، وتاريخ مراجعة مفقود أو غير صالح أو أقدم من 180 يومًا. الفحص **لا يثبت عمل الهاتف أو انتهاء التعاقد**. يؤخذ استقبال المستشفى صراحة عند وجود معرّف ربط بها ورقم صالح، دون إنشاء ربط من تشابه الاسم.
- مسودات المحتوى ومراجعه غير المكتملة، وانتهاء عرض المادة أو سريان تعليماتها، واقتراب انتهاء ذلك خلال سبعة أيام. هذا مختلف عن انتهاء تعاقد جهة طبية. المؤرشف لا يولد عملًا جديدًا تلقائيًا.
- الأولوية لتنظيم **مراجعة البيانات**، وليست فرز حالات طبية. لا مدد خدمة مفترضة للشركة ولا تصنيف جودة طبي من النواقص.
- تعرض الافتراضات الأولى الجهات الظاهرة والملاحظات التي تحتاج انتباهًا، وتستبعد السجلات المنجزة في إدارة الدليل. البحث يتيح العثور عليها، ويمكن اختيار «كل السجلات» و«الظاهرة والمحجوبة» و«كل الحالات». متابعة اختارها المدير أو معلومة تغيرت بعد متابعته لا تعد عملًا منجزًا بمجرد وجود مراجعة مركزية سابقة.
- فتح السجل ينقل إلى قائمة الإدارة بتصفية ومعرّف واضحين، ولا يفتح حفظًا أو يعدل مباشرة. المعرّف الملتبس لا يوجه إلى سجل مخمن، ويحال إلى قائمة الجودة. العودة تحفظ بحث المكتب وفلاتره في ذاكرة الصفحة، وتمسح بتبديل الهوية والخروج.

## متابعتي الخاصة

يمكن تسجيل «جديد / قيد المتابعة / مؤجل / راجعته»، مع سبب من قائمة مغلقة وموعد متابعة اختياري. التأجيل ليوم لاحق، والموعد خلال 90 يومًا بتوقيت القاهرة. حلول الموعد يعرض «حان موعد متابعته» عند قراءة المكتب؛ **لا يرسل تذكيرًا خارجيًا أو إشعارًا لعضو**. السبب «انتظار رد الجهة» وصف يسجله المدير، وليس ادعاء أن النظام تواصل معها.

«راجعته» يخص قائمة المدير وحدها. لا يحسم طلبًا أو ينشر تقييمًا أو يؤكد تصحيح المعلومة ميدانيًا. إذا تغير المحتوى المؤثر للملاحظة، يظهر «تغيرت بياناته»، ويبطل سريان حكم المتابعة والتأجيل القديم على نسختها الحالية. لا تؤثر إعادة حفظ السجل دون تغير محتواه أو وقت مراجعته المركزي وحده على البصمة.

إذا اختفت الملاحظة من الفحص يظهر ذلك في السجل الخاص، دون ادعاء تحقق ميداني. وإذا اختفى سجل الجهة نفسه يظهر أنه لم يعد متاحًا. يمكن حذف المتابعة الخاصة صراحة؛ لا يحذف هذا سجل الجهة ولا سجل طلب أو تقييم.

النسخة المتوقعة ومعرّف العملية يحميان تعارض الأجهزة وإعادة الحفظ بعد فقد الرد. يثبت النموذج النسخة والبصمة عند فتحه؛ إذا تغيّرتا لا يتبنى القيم الجديدة بصمت، بل يتطلب الإلغاء وإعادة الفتح. يُفحص إيقاف العينة مرة أخرى داخل معاملة الكتابة. لا يستقبل هذا المسار أسماء أعضاء أو ملاحظات حرة أو بيانات صحية أو تعليمات نشر.

## الخصوصية والحدود

الحفظ في `medical_lab_workspaces` داخل Medical، بمسار مشتق من هوية المدير الخادمية. لا يستطيع مدير آخر قراءة سجل المتابعة أو حذفه بتمرير هوية في الطلب. التدقيق يحفظ نوع العملية والنسخة والهوية والوقت، دون نسخ النصوص أو محتوى طلبات الأعضاء.

حد 200 متابعة للحساب، و20 حدثًا للمتابعة، و700000 بايت للحالة، و40 معرف إعادة عملية؛ لا إزاحة صامتة للتاريخ. تعرض اللقطة حتى 1000 ملاحظة مع العدد الإجمالي وتحذير ظاهر إن تجاوزته، ويكون البحث داخل اللقطة المعروضة. تعرض القائمة على دفعات محلية من 24 لتناسب الهاتف. هذه حدود معاينة وليست ادعاء دعم غير محدود لدليل الجمهورية.

التصدير **تقرير أعداد فقط**: وقت اللقطة والأعداد المتاحة أو المجهولة وعدد الملاحظات والفئات والمتابعات، دون أسماء جهات أو أعضاء أو تفاصيل سجل خاص أو استعلام البحث. إذا اقتطعت اللقطة يذكر التقرير ذلك، وتخص أعداد الفئات العناصر المحملة فقط. لا يعد تنزيل التقرير تحديثًا تلقائيًا لبياناته.

التحقق الدوري كل 20 ثانية وعند العودة للتبويب يقرأ صلاحية المدير وحالة العينة ونسخة مساحته؛ **لا يعيد استعلامات الأعداد أو الدليل في كل فحص** ولا يمدد الجلسة. يتحدث المصدر عند «تحديث المكتب»، أو عند إعادة تحميل المساحة بعد تغيرها. يظهر وقت لقطة البيانات بوضوح. يخفى المحتوى عند فقد الاتصال أو التحقق، ولا تعيد استجابة متأخرة ملء صفحة غادرها المدير.

## الجاهزية والتشغيل

لوحة جاهزية P0 أضيف لها المكتب وعدد المتابعات الخاصة المحفوظة فقط، بمراجعة `p0-readiness-20261023-1`. تبقى اللوائح والخصوصية والنسخ والاستعادة والتكلفة والتفعيل للأعضاء بتبعياتها السابقة؛ تجهيز المكتب لا يكملها تلقائيًا.

قدرة الخلفية الجديدة **`development-admin-inbox-v1`**، والواجهة **4.20.0**. فحص بداية المهمة أثبت نشر `development-catalog-plans-v1` للمرحلة السابقة. لا توجد هوية Google متصلة ببيئة التنفيذ؛ ينشر المالك خدمة Medical من Cloud Shell:

```bash
cd ~/cloudshell_open/Medical && git pull --ff-only origin main && bash scripts/deploy-medical.sh --existing-config
```

ثم فحص دون تسجيل دخول أو قراءة بيانات خاصة:

```bash
NODE_USE_ENV_PROXY=1 node scripts/check-live.mjs --require-admin-inbox --require-catalog-plans --require-catalog-staging --require-service-workflow --require-development-lab --rayati --vercel
```

الرجوع بإيقاف عينة المكتب من المعمل؛ تظل المتابعات محفوظة ولا يتغير التشغيل. نشر Vercel وPages مختلف عن نشر Firebase، ولا يثبت نجاح مهمة الجاهزية في GitHub نشر الخدمة عندما يكون عمل النشر متجاوزًا لغياب إعداد هوية Google.

## الفحوص

اختبارات ببيانات مصطنعة للتجميع دون قراءة بيانات شخصية، وفشل مصدر عددي دون تصفيره، وإسقاط الحقول الزائدة، والصلاحيات الحية وعزل المديرين، وتعارض النسخ وإعادة الطلب والإيقاف داخل المعاملة، وتغير المصدر والسجلات المنجزة والمواعيد بتوقيت القاهرة وحدود السجل. اختبارات HTTP لمساري القراءة والحفظ وترويسات منع التخزين، ومحاكي Firestore لاستعلامات الأعداد والمعاملات وثبات بيانات التشغيل والمصدر. المتصفح يجرب الفلاتر والرجوع وحفظ المتابعة وفقد الرد وتغير المصدر والحجب، بمقاسات 320–1440. يسجل تقرير التسليم النتيجة الفعلية بعد إكمال الفحوص.

نتيجة التحقق المحلي في 23 أكتوبر 2026: **197 اختبار وحدة وحماية ناجحًا**، ورحلة المتصفح الكاملة ناجحة دون أخطاء تشغيل، واختبار Firestore Emulator ناجح، والبناء وفحص الأصول ناجحان. شملت رحلة المتصفح العودة للبحث السابق، وتسجيل المتابعة والتأجيل، وإعادة العملية بعد فقد الرد دون مضاعفة السجل، وتغير المصدر، وتعذر قراءة أحد الأعداد، وإيقاف المكتب، ومقاسات 320–1440. أثبتت اختبارات المحاكي بقاء دليل الأعضاء ومصدرهم دون تغيير. لا تثبت هذه النتائج وحدها نشر Firebase الجديد أو تسجيل دخول إنتاج خاص، ولا توجد هوية Google متصلة للنشر من هذه البيئة.
