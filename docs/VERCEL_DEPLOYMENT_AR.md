# ربط Medical بـVercel

## ما تم تجهيزه

- `vercel.json` يحدد موقعًا ثابتًا، ويبني ملفات النشر بأمر `node scripts/build-static.mjs`، ثم ينشر `dist`.
- لا يحتاج البناء إلى حزم أو مفاتيح Firebase.
- ناتج النشر يضم `index.html` و`manifest.json` و`sw.js` ومجلدات `css` و`js` و`img` فقط. ملفات Excel والتقارير وأدوات التوليد لا تدخل الناتج.
- تعطيل التخزين الطويل لملف Service Worker يتيح فحص تحديثاته؛ هذا لا يستبدل إصلاح استراتيجية التخزين داخل العامل المذكورة في التقرير.
- `.vercel/` وملفات البيئة محجوبة عن Git. لا تُشارك جلسات أو إعدادات المشاريع الأخرى.

## إعداد مشروع Vercel

1. استيراد المستودع `abomawadda/Medical` في مشروع Vercel مستقل، مثل `medical` إذا كان الاسم متاحًا.
2. اختيار الفريق الصحيح، وفرع الإنتاج `main`، وجذر المستودع `.`، ونوع الإطار `Other`.
3. استخدام إعدادات المستودع: Build Command = `node scripts/build-static.mjs`، Output Directory = `dist`، وInstall Command فارغ. لا يلزم متغير بيئة لهذه النسخة الثابتة.
4. النشر ثم تسجيل رابط الإنتاج الذي تعيده Vercel فعلًا؛ لا يُفترض توفر عنوان بعينه قبل إتمام الإنشاء.

## التحقق بعد الربط

- ظهور ربط Git بالمستودع الصحيح والفرع `main` في إعدادات Vercel، ونجاح النشر الآلي للالتزامات اللاحقة.
- استجابة الصفحة وملفات JavaScript والصور و`manifest.json` و`sw.js` بنجاح.
- تطابق ملف `js/app.js` المنشور مع الالتزام المستهدف.
- نجاح البحث والتبديل بين الأقسام وروابط `#doctors` و`#emergency` على الهاتف.
- عدم تقديم ملف Excel أو تقارير الفحص من مجلد النشر.
- عدم وجود أي كتابة إلى Firebase الخاص بـMyNekaba؛ هذا الإصدار لا يتصل به أصلًا.

## حالة التنفيذ عند إعداد هذا الملف

تجهيز المستودع والبناء المحلي لا يعني إنشاء مشروع داخل حساب Vercel. لم تتوفر جلسة Vercel أو إضافة متصلة أثناء الإعداد، لذلك يبقى إنشاء الربط والتحقق من رابط الإنتاج معلقًا إلى أن يتوفر اتصال الحساب. لا توجد في هذا الملف مطالبة بأن النشر قد تم.
