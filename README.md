## الإصدار 4

- البحث في الأطباء والمستشفيات والمعامل والأشعة والصيدليات والمراكز المتخصصة، مع تصفية مقار العمل والمواعيد ووسائل التواصل.
- بيانات الإصدار المعدّ: 170 سجل مقر في 157 بطاقة طبيب/قسم، و15 تخصصًا، و15 مستشفى و87 مرفق خدمة؛ وصول الإضافات إلى API يحتاج نشر Firebase كما في تقرير الاستيراد.
- اختيار مقر العمل يحدث زر الاتصال والخريطة معًا؛ شروط البحث تطبق على المقر نفسه. لكل جهة رابط قابل للمشاركة.
- المفضلة والمظهر يحفظان على الجهاز فقط. يدعم الدليل العمل دون الإنترنت بعد تحميله، مع إصدار تخزين مشتق من ملفات الإصدار، دون تخزين استجابات API في عامل الخدمة. استعادة الدخول بعد إعادة فتح التطبيق تحتاج الإنترنت للتحقق من الجلسة.
- خيار «تذكّر دخولي» يحتفظ برمز جلسة لمدة تصل إلى 30 يومًا على الجهاز الشخصي، دون حفظ كود الموظف أو الموبايل أو أرقام الهوية. بدون هذا الخيار تستمر الجلسة في التبويب لمدة 30 دقيقة، ويزيل تسجيل الخروج الرمز المحفوظ ويلغي الجلسة على الخادم.
- بطاقة العضو تعرض بياناته الوظيفية والنقابية وآخر دخول إلى Medical من خدمة محمية، دون حفظ بياناته الشخصية في المتصفح. تحتاج وظيفة Firebase المحدثة.
- تقييم بنسخ: العضو وحده يعدل المحتوى، وكل تعديل فعلي يعود للمراجعة، وإعادة اعتماد النسخة نفسها لا تكرر النجوم أو سجل التدقيق.
- استعيد خط Cairo للنصوص وخط Tajawal للعناوين، بملفات WOFF2 محلية مرخصة تحت SIL OFL.
- العضو يدخل بكود الموظف والموبايل المسجل وآخر أربعة أرقام من الرقم القومي، بعد مطابقتها على الخادم. لا حسابات أعضاء جديدة أو OTP أو Firebase Auth للأعضاء.
- التقييم والملاحظات مرتبطان بهوية العضو الخادمية وبمقر زيارته، ويحتاجان اتصالًا بالإنترنت. التقييمات المعلقة لا تدخل المتوسط العام قبل مراجعة المدير. الملاحظات للكاتب والمدير فقط.
- المدير هو حساب MyNekaba المعتمد بالمعرف، بدور فعال يتحقق منه الخادم. لا رموز ثابتة أو ترقيات عبر المتصفح.

## حالة التفعيل

تتطلب شاشات الدليل تسجيل الدخول أولًا، بما في ذلك الروابط المباشرة. لا ينزّل المتصفح ملف الدليل العام ضمن ملفات الواجهة، ويتطلب مسار بيانات الدليل جلسة يتحقق منها الخادم. **تشغيل الدخول والتقييمات والإدارة المركزية يحتاج نشر خدمة Medical وتهيئة عنوانها في `js/config.js`.** ما دام العنوان فارغًا تظهر شاشة الدخول وحالة التجهيز، وتتعطل نماذج الدخول والتصفح؛ لا توجد حسابات تجريبية أو نجاح حفظ وهمي. لا يعني نشر الواجهة اكتمال الربط مع Firebase.

تحتاج الخدمة مشروع Firebase مستقلًا وقراءة معتمدة من مصدر العضوية؛ لا يكتب التطبيق في Firestore الخاص بـMyNekaba، ولا يعدل كوده أو قواعده. توافق حساب المدير الحالي مع Firebase Email/Password يحتاج إثباتًا قبل التفعيل؛ لا يجري ترحيل الحسابات القديمة أو تغيير claims تلقائيًا. التفاصيل في [دليل تشغيل الخدمة](docs/BACKEND_SETUP_AR.md).

## التطوير والتحقق

```sh
npm ci --ignore-scripts
npm test
python3 build_dataset.py
node scripts/prepare-seed.mjs
npm run build
npm run check
npx playwright install chromium
npm run test:browser
```

اختبارات المتصفح تستخدم بيانات مصطنعة وخدمة محلية مشتركة، وتختبر الدخول والتقييم والإدارة والعزل والعمل دون اتصال؛ لا تتصل بحسابات أعضاء حقيقية. يمكن تحديد Chromium محليًا بمتغير `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

لاختبار محول Firestore ومعاملاته الفعلية في محاكي محلي، بعد تثبيت اعتماديات `functions` وJava 21:

```sh
npm ci --prefix functions --ignore-scripts
npx firebase-tools@15.34.0 emulators:exec --only firestore --project demo-medical 'node functions/test/firestore.integration.mjs'
```

الاختبار يحظر الوصول إلى الإنتاج، ويستخدم مشروعي `demo-*` محليين. لا يثبت وحده صحة IAM في بيئة الإنتاج.

## بنية الملفات والنشر

- `js/app.js`: واجهة تستخدم عناصر DOM ونصوصًا آمنة، دون إدراج البيانات كـHTML.
- `js/api.js`: جلسة في ذاكرة الصفحة واتصال بالخدمة؛ لا أسرار في إعداد الواجهة.
- `functions/src/core.mjs`: التحقق والصلاحيات والتقييمات وقواعد الإدارة.
- `functions/src/firebase-adapters.mjs`: تخزين Medical ومعاملاته، ومحول قراءة منفصل لمصدر العضوية.
- `firebase/medical.firestore.rules`: منع الوصول المباشر إلى قاعدة Medical من المتصفح.
- `scripts/build-static.mjs`: يبني `dist` ويحدث إصدار عامل الخدمة في الجذر؛ شغله قبل نشر تغييرات الواجهة.
- `_config.yml`: يستثني الكود الخلفي وملفات المصدر والأدلة وExcel من نشر GitHub Pages الحالي من جذر `main`.
- `.github/workflows/pages.yml`: يتحقق من الكود والبيانات واختبارات المتصفح ويحتفظ بناتج البناء. النشر الحالي يبقى عبر إعداد Pages الموجود؛ لا يغيّر هذا الملف إعداداته.

ملفات `dist` لا تحتوي إلا أصول التطبيق. إعداد Vercel محفوظ للاستخدام المستقبلي، وهو مؤجل حاليًا. لا يحتاج الموقع واجهة جديدة أو نطاقًا مختلفًا للاستفادة من الخدمة الخلفية.

## حدود البيانات

لا يحتوي الملف العام على كشف العاملين، ولا توجد نجوم أو أعداد تقييمات مولدة. ادعاءات التغطية وأرقام الجهات تحتاج مصادر وتواريخ مراجعة؛ القيم غير المؤكدة تعرض كذلك. لا تثبت مطابقة بيانات العضو حصول الزيارة أو ملكية الهاتف. أُزيل رقم التنسيق التجريبي القديم بدل عرضه كرقم طوارئ حقيقي؛ يضيفه المدير بعد التأكد منه.

بيانات الأطباء الحالية مركزة في المنصورة وطلخا؛ قوائم المدن لا تعني اكتمال التغطية الجغرافية. التأكد من صلاحية التعاقد والمواعيد ومسؤولية الخدمة الطبية يبقى لدى الجهة المختصة.

حجب التصفح داخل التطبيق لا يحوّل مستودع GitHub العام إلى مستودع خاص؛ ملفات مصدر بيانات الجهات ما زالت جزءًا من المستودع. الملاحظات وبيانات العضوية لا تُحفظ فيه.
